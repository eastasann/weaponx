# weaponx — 設計仕様書

> **資料の管理をアプリが引き受け、案件・参考資料・版を作った時点で記録する。資料が増えても「どれが最新で、何を参考にしたか」が一覧で分かる。**

---

## 1. プロダクト概要

### 1.1 コンセプト

案件ごとにスライドとドキュメントが増え続ける職種(コンサル・営業・リサーチ職など)に向けた資料管理ツール。資料が増えると、資料どうしの関連・最新版・読むべきものが分からなくなる。この課題を、散らかった後に推測して見える化するのではなく、資料を作った(登録した)時点で「どの案件か」「何を参考にしたか」「どれの新しい版か」を事実として記録することで解く。

- 対象: 案件ごとに資料が増え続ける人。まず作者自身が日常で使い、同じ職場の人にも広げる
- 管理の単位: 案件。資料は1つの案件に属し、案件の中では1行に1系列(同じ資料の版の並び)の最新版が並ぶ
- 関連の種類: 参考資料(この資料を作るときに参考にした資料)と版(同じ資料の新しい版)の2種類。どちらも推測せず、人の記録か、アプリの「これを元に作る」「新しい版を作る」操作で決まる
- 版の意味: 版は別ファイルとして作られた資料を指す。同じファイルを上書き編集しても版は増えず、更新日時が変わるだけ
- 書く・作る道具: 持たない。Google ドキュメント・スライドなど既存の道具を借り、アプリは管理に徹する

経緯: Phase 0 の `docs/concept.md` は「ドライブの資料を後から読んで関連を地図に描く」だった。Phase 1 の壁打ちで上記に見直した(`docs/brainstorm-notes.md` の「コンセプトからの見直し」)。

### 1.2 プロダクト方針

| 項目 | 方針 |
|------|------|
| 用途 | 自分用の MVP。課金なし。同じ職場の人も招待して使える |
| 対応言語 | 日本語と英語。詳細は下の「言語と表示の規則」 |
| 端末 | デスクトップ優先。スマホでは「案件と資料を探して開く」ことだけができる(6.6) |
| ドライブ連携 | 任意。つながなくても中核(案件・リンク登録・参考資料と版の記録・一覧・検索・招待)は使える。つないだ人は、資料名と更新日時を自動で取れ、アプリから Google ドキュメント・スライドを作れる |
| 資料の実体 | 元の場所(ドライブ・Box・社内サーバ等)に置いたまま。アプリはリンクと管理情報だけを持つ |
| 元の場所への作用 | アプリは元の場所のファイルを消さない・書き換えない。例外は、連携ありの人の操作で新しいファイルを作る(空の資料の作成と、既存資料のコピー)ことだけ |
| Google の資料の名前 | 元の場所から取得できた資料名と更新日時を正とする。アプリ上では書き換えない(名前を変えたいときはドライブで変える) |
| 本文 | 保存しない。関連を推測しないので本文を読む必要がない。検索は資料名だけを対象にする |
| 権限の効き方 | 案件内の役割はアプリ上の管理情報に効く。資料そのものを開けるかは、元の場所の権限に従う。ドライブの共有設定は同期しない |
| 一覧の件数 | MVP の一覧(案件・資料・メンバー・利用者)はページ分けせず全件を出す。想定規模は、1人あたりの参加案件が数十件、1案件の系列が数百件まで。横断検索の結果だけ50件で打ち切る |

言語と表示の規則:

- 画面の文言はすべて日本語と英語の2言語で用意する。文言は翻訳ファイルで管理し、英語の文言は Phase 3 以降の実装で確定する。主な用語の英語は 1.4 に従う
- 翻訳しないもの: 利用者が入力した内容(案件名・資料名など)、元の場所から取得した資料名、Google から取得した表示名、アプリ名 weaponx
- 表示言語の決め方:
  - ログイン前: ブラウザに保存した選択があればそれを、無ければブラウザの言語設定を使う(日本語なら日本語、それ以外は英語)。ログイン画面で切り替えた値はブラウザに保存する
  - ログイン時: users.locale が空なら、そのときの表示言語を users.locale に保存する。users.locale に値があればそれを使う
  - ログイン後: ユーザーメニューで切り替えると users.locale とブラウザの両方に保存する
- 件数の英語は単数と複数を区別する(1 document / 2 documents)
- 日時の書式(タイムゾーンはブラウザのもの):

| 種類 | 日本語 | 英語 | 使う場所 |
|------|--------|------|---------|
| 日付 | 2026/09/28 | Sep 28, 2026 | 一覧の列、横パネルの版の欄、検索結果、追加日 |
| 日時 | 2026/09/28 14:05 | Sep 28, 2026, 2:05 PM | 連携した日時、最終ログイン、横パネルの概要の更新日時 |

- 名前で並べ替えるときは、表示言語の辞書順に従う

### 1.3 UI設計原則

| 原則 | 内容 |
|------|------|
| 最新版が主役 | 一覧には常に最新版だけを並べる。旧版は求められたときだけ横パネルで見せる。「読むべきなのはこの行」を崩さない |
| 記録は操作のついで | 「これを元に作る」「新しい版を作る」では参考資料と版が自動で記録される。人が手で関連を選ぶのは、資料を登録・編集するときの参考資料欄だけにする |
| 開くまで最短 | 一覧の行にマウスを載せると「開く」アイコンが出て、横パネルを開かずに元の場所へ行ける |
| 使えない操作の見せ方 | 役割・端末・資料の種別・連携の有無で使えない操作のボタンは表示しない(連携なしの人には、代わりに連携の案内を1行出す)。それ以外の条件でできない操作(最後のオーナーを外す、自分自身を停止するなど)は、ボタンを無効化して理由を添える |
| 元の場所が正 | 資料の中身・名前・共有は元の場所が決める。アプリは開けない資料を開けるようには見せない。権限のない他案件の資料は「見る権限のない資料」とだけ表示する |
| 高密度で見渡す | 行を詰め、1画面に多くの資料を並べる。装飾より資料名と関連を目立たせる |

### 1.4 用語

画面の文言と仕様書で使う言葉。英語は画面の英語表記に使う。

| 日本語 | 英語 | 意味 |
|--------|------|------|
| 案件 | Project | 資料をまとめる単位。メンバーと役割を持つ |
| 資料 | Document | 元の場所にあるファイルへのリンクと、その管理情報 |
| 版 | Version | 同じ資料の、別ファイルとして作られた各回。v1, v2, … と数える |
| 最新版 | Latest | 系列のうち、削除されていない最大の版 |
| 旧版 | Older versions | 最新版より前の、削除されていない版 |
| 参考資料 | References | この資料を作るときに参考にした資料。スライド巻末に付ける補足資料の意味ではない |
| この資料を参考にした資料 | Referenced by | この資料を参考資料にしている資料 |
| これを元に作る | Create from this | 選んだ資料をコピーして、新しい資料を作る操作 |
| 新しい版を作る | Create new version | 最新版をコピーして、同じ系列の次の版を作る操作 |
| 登録した人 | Added by | その版をアプリに登録した(作った)人 |
| 横パネル | (画面には出さない) | 案件画面で資料を選んだときに右側に開く欄 |
| 要再連携 | Reconnection needed | ドライブ連携の許可が切れた状態。画面の文言は「ドライブ連携の有効期限が切れました」 |
| 系列 | (画面には出さない) | 同じ資料の版の並び。一覧の1行にあたる。仕様書とデータモデルだけで使う |

## 2. ユーザーロールとフロー

### 2.1 ロール定義

全体のロール(アプリ全体で1人に1つ):

| ロール | 概要 | 主な操作 |
|--------|------|----------|
| 一般ユーザー | 管理者に許可された Google アカウントで入り、案件と資料を管理する人 | 案件の作成、参加している案件での役割に応じた操作、横断検索、自分のドライブ連携のつなぐ・外す、表示言語の切り替え |
| 管理者 | 使える人を管理する人 | 一般ユーザーの操作 + 利用者の追加・停止・再開、管理者の付与・解除 |

案件内の役割(案件ごとに1人に1つ):

| 役割 | 概要 | 主な操作 |
|------|------|----------|
| オーナー | 案件の責任者。複数置ける | 編集者の操作 + メンバーの招待・役割の変更・外す、案件名の変更、案件の削除 |
| 編集者 | 案件の資料を管理する人 | 閲覧者の操作 + 資料の追加、新しい版の登録、これを元に作る・新しい版を作る(連携ありのみ)、登録内容の編集、版の削除 |
| 閲覧者 | 案件の資料を見るだけの人 | 資料一覧・関連・版の閲覧、資料を開く、メンバー一覧の閲覧 |

権限の規則:

- 管理者でも、参加していない案件の案件名・資料・メンバーは見られない。例外は、停止の確認画面に出す「唯一のオーナーになっている案件の件数」だけ
- 案件の作成者は、その案件の最初のオーナーになる
- 削除されていない案件には、オーナーが常に1人以上いる。最後のオーナーは、自分を外すことも自分の役割を変えることもできない
- 管理者は常に1人以上いる。管理者は自分自身を停止することも、自分の管理者を外すこともできない
- 停止された利用者はログインできない。案件での役割・登録した資料・登録した人としての名前表示は残る
- 役割が変わった・メンバーから外された・停止されたときは、その人の次の操作から反映する(6.0.2)
- 最初の管理者は初期設定で登録する(手順は Phase 3 で決める)

### 2.2 フロー全体像

```
全員(探して開く・コアフロー):
  ログイン → ホーム(案件一覧) → 案件 → 資料を選ぶ → 横パネルで参考資料・版・参考にした資料をたどる → 開く(別タブ)

全員(横断で探す):
  ホーム → 検索欄に資料名を入力 → 結果の資料を選ぶ → 案件(その資料を選んだ状態) → 開く(別タブ)

編集者以上(リンクで登録する):
  案件 → 資料を追加 → リンクを貼る → 名前・種別・参考資料を入力 → 一覧に並ぶ

編集者以上・連携あり(新しく作る):
  案件 → 資料を追加 → 新しく作る → 種別・名前・参考資料を入力 → 一覧に並び、編集画面が別タブで開く

編集者以上(新しい版を登録する):
  案件 → 資料を選ぶ → 新しい版を登録 → リンクを貼る → 系列の最新版になる

編集者以上・連携あり(これを元に作る / 新しい版を作る):
  案件 → 資料を選ぶ → これを元に作る / 新しい版を作る → 名前・追加先を確認 → 編集画面が別タブで開く(参考資料・版は自動で記録)

オーナー:
  案件 → メンバー → 招待・役割の変更・外す

管理者:
  ユーザーメニュー → 利用者管理 → 利用者の追加・停止・再開、管理者の付与・解除
```

## 3. 画面一覧

画面の存在・目的・レイアウト・認証要否はこのドキュメントが所有する。レイアウトパターン(P1〜P4)の定義は 4.1 を参照。

### 3.1 共通画面

| 画面名 | 目的 | 説明 | レイアウト | 認証 |
|--------|------|------|-----------|------|
| ログイン | 利用を始める | Google アカウントでログインする。許可されていない・停止されたアカウントには理由を表示する。ログイン前でも表示言語を切り替えられる | P1 中央集中 | 不要 |
| エラー | 開けないページを知らせる | 存在しない URL(ページが見つかりません)と、想定外の障害(問題が発生しました)を表示し、戻り先を出す | P1 中央集中 | 不要 |

### 3.2 一般ユーザー面(管理者も使う)

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| U1 | ホーム | 案件を選ぶ・作る、資料を横断で探す | 参加している案件の一覧と「案件を作る」。検索欄に入力すると、参加している全案件の資料を資料名で検索し、案件一覧の場所に結果を出す | P3 一覧 | 要 |
| U2 | 案件 | 資料を探して開く(コア画面) | 資料を表形式で並べる。1行は1系列の最新版。資料を選ぶと右に横パネルが開き、版・参考資料・参考にした資料と操作を出す | P2 一覧 + 横パネル | 要(案件のメンバーのみ) |
| U3 | メンバー管理 | 案件の参加者を管理する | 案件のメンバー一覧。オーナーは招待・役割の変更・外すができる。他の役割は閲覧だけ | P3 一覧 | 要(案件のメンバーのみ) |
| U4 | 連携設定 | ドライブ連携を管理する | 連携の状態を表示し、つなぐ・外す・つなぎ直すを行う | P4 設定フォーム | 要 |

### 3.3 管理者面

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| A1 | 利用者管理 | 使える人を管理する | 利用者の一覧。追加・停止・再開・管理者の付与と解除 | P3 一覧 | 要(管理者のみ) |

### 3.4 ダイアログ一覧

画面ではなく、画面の上に重ねて開くダイアログ(パターン D)。

| ダイアログ | 開く場所 | 目的 | 対象 |
|-----------|---------|------|------|
| 案件を作る | ホーム | 案件名を入れて案件を作る | 全員 |
| 資料を追加 | 案件 | リンクで登録する。連携ありなら新しく作ることもできる | 編集者以上 |
| 新しい版を登録 | 案件(横パネル) | リンクを貼って系列の新しい版として登録する | 編集者以上 |
| 作成(これを元に作る / 新しい版を作る) | 案件(横パネル) | 選んだ資料をコピーして新しい資料・新しい版を作る | 編集者以上・連携あり |
| 登録内容を編集 | 案件(横パネル) | 選んだ版のリンク・種別・参考資料を直す。資料名と更新日時は、Google から取得済みでなければ直せる(6.5.6) | 編集者以上 |
| 案件名を変更 | 案件 | 案件名を直す | オーナー |
| メンバーを招待 | メンバー管理 | 許可済みの利用者を選び、役割を決めて招待する | オーナー |
| 利用者を追加 | 利用者管理 | 利用を許可する Google アカウントを追加する | 管理者 |
| 確認ダイアログ | 各画面 | 版・案件の削除、メンバーを外す、自分の役割を下げる、連携の解除、利用者の停止など、取り消しにくい操作の前に確認する | 操作できる人 |

### 3.5 ログイン・エラー以外の全画面に共通の要素

- ヘッダー: 左にアプリ名 weaponx(押すとホーム)。右にユーザーアイコン。アイコンを押すとユーザーメニューが開く
- ユーザーメニュー: 表示言語(日本語 / English)、連携設定、利用者管理(管理者にだけ表示)、ログアウト。モバイルでは連携設定と利用者管理を出さない
- 要再連携の帯: ドライブ連携が要再連携のとき、ヘッダーの下に警告色で「ドライブ連携の有効期限が切れました」と「連携設定へ」を表示する。モバイルでは出さない
- 通知: 画面上部に数秒出て消える通知(成功・失敗の知らせ)。失敗の通知は自分で閉じるまで残す

## 4. デザインシステム

### 4.1 レイアウトパターン定義

| パターン | 形 | 使う場面 |
|---------|-----|---------|
| P1 中央集中 | 画面中央に1枚のカード。ヘッダーなし | ログイン前や、開けないページを知らせる、1つの操作だけに注目させる画面 |
| P2 一覧 + 横パネル | 上にツールバー、下に全幅の表。行を選ぶと右側に横パネルが開き、表の幅が縮む。閉じると全幅に戻る | 一覧を見ながら、選んだ1件の詳細と関連をたどる画面 |
| P3 一覧 | 上にページ見出しとツールバー(検索欄・主操作ボタン)、下に全幅の表 | 同じ種類のものを並べて選ぶ・管理する画面 |
| P4 設定フォーム | 幅を絞った1カラムに、状態表示と操作を縦に並べる | 1つの設定の状態を確認して変える画面 |
| D ダイアログ | 画面中央に重ねるモーダル。背面は暗くし、操作できない | 画面を離れずに短い入力をする場面 |

### 4.2 画面 × レイアウト マッピング

| # | 画面 | パターン | スクロール | 根拠 |
|---|------|----------|-----------|------|
| - | ログイン | P1 | なし | ログインボタン1つに注目させる |
| - | エラー | P1 | なし | 何が起きたかと戻り先だけを見せる |
| U1 | ホーム | P3 | 表だけ縦にスクロール(ヘッダー・ツールバーは固定) | 案件を並べて選ぶ。検索結果も同じ表の形で出す |
| U2 | 案件 | P2 | 表と横パネルがそれぞれ独立して縦にスクロール | 一覧を見たまま版・参考資料・参考にした資料をたどるのがコアフロー |
| U3 | メンバー管理 | P3 | 表だけ縦にスクロール | メンバーを並べて役割を管理する |
| U4 | 連携設定 | P4 | 通常は収まる | 連携の状態1つを確認して変える |
| A1 | 利用者管理 | P3 | 表だけ縦にスクロール | 利用者を並べて状態を管理する |

### 4.3 レスポンシブ方針

| ブレイクポイント | 幅 | 対応 |
|-----------------|-----|------|
| デスクトップ | ≥1024px | すべての機能を提供する。P2 の横パネルは表の右に並べる |
| タブレット | 768〜1023px | すべての機能を提供する。P2 の横パネルは表の上に重ねて右から出す(表の幅は縮めない) |
| モバイル | <768px | 「探して開く」だけを提供する。詳細は 6.6 |

### 4.4 ビジュアルデザイン方針

具体的な値(色コード・フォントサイズ等)は Phase 3 で `docs/06_design-tokens.json` として確定する。ここでは方向性だけを決める。

| 項目 | 方針 |
|------|------|
| トーン&ムード | 落ち着いた業務系。装飾を抑え、資料の名前と関連が主役になる見た目。職場で他の人に見られても浮かない |

## 6. コア画面詳細仕様

### 6.0 全画面に共通の規則

各画面の仕様に書いていない場合は、この規則に従う。

#### 6.0.1 読み込み・操作中・成功

| 場面 | 表示 |
|------|------|
| 画面・表の読み込み中 | 見出しとツールバーを先に出し、表は灰色の仮の行を出す(行数は各画面の仕様) |
| ボタンの操作中 | 押したボタンを読み込み中の表示にし、同じボタンを押せなくする。ダイアログは閉じない |
| 操作の成功 | 通知で知らせる(例:「資料を追加しました」「役割を変更しました」)。画面の表示を最新の状態に更新する |

#### 6.0.2 失敗の分類と振る舞い

サーバーから返る失敗を次の5つに分け、画面ごとに同じ振る舞いをする。

| 分類 | 起きる例 | 文言 | 画面の動き |
|------|---------|------|-----------|
| 見つからない | 選んでいた版・系列・案件が他の人に削除された。削除済みの版に新しい版の登録や編集をしようとした | 「この資料は削除されたか、見つかりません」(案件なら「この案件は見つからないか、参加していません」) | ダイアログを閉じ、表を読み込み直す。横パネルで開いていた資料が無くなったら横パネルを閉じる。案件が無くなったら案件画面全体を「見つからない」表示にする |
| 権限がない | 自分がメンバーから外された・役割を下げられた・停止された・管理者を外された | 「この操作を行う権限がありません」 | 外された・案件が見えなくなった場合は案件画面全体を「見つからない」表示にする。役割が下がった場合は画面を読み込み直し、新しい役割に合わせてボタンを出し直す。停止された場合はログイン画面へ送り、停止の表示を出す |
| 入力の問題 | 検証エラー、リンクの重複、参考資料に選んだ資料が削除された・見えなくなった、招待しようとした人が停止された・すでにメンバーになっていた、最後のオーナー・最後の管理者を外そうとした | 理由を具体的に出す(各画面の仕様) | ダイアログは閉じず、入力を保つ。該当する欄の下に理由を出す。削除された参考資料はチップを外して理由を出す |
| 要再連携 | ドライブの操作で Google が認可エラーを返した | 「ドライブ連携の有効期限が切れました」と「連携設定へ」 | ダイアログは閉じず、入力を保つ。連携の状態を要再連携に切り替える |
| 通信・その他 | ネットワークの切断、サーバーの障害 | 「保存できませんでした。もう一度お試しください」(読み込みなら「読み込めませんでした」と「再読み込み」) | ダイアログは閉じず、入力を保つ |

#### 6.0.3 入力の共通規則

- 文字列は前後の空白を取り除いてから検証する。空白だけの入力は空とみなす。改行は受け付けない(1行入力)
- 文字数は見た目の1文字を1と数える
- 上限: 案件名 100文字、資料名 200文字、リンク 2048文字、検索語 100文字、1つの版の参考資料 20件
- 検証エラーは欄の下に理由を出し、確定ボタン(追加・作成・保存・招待)を押せなくする
- 文言の例: 「入力してください」「{n}文字以内で入力してください」「http または https で始まるリンクを入力してください」「参考資料は20件まで選べます」

#### 6.0.4 リンクの重複

- 同じ案件の中で、削除されていない版どうしは同じリンクを持てない。別の案件に同じリンクがあるのは許す
- 比べ方: Google の資料は URL から取り出したファイル ID(google_file_id)で比べる。それ以外は前後の空白を除いた URL の文字列で比べる
- 確認する操作: 資料の追加、新しい版の登録、登録内容の編集でリンクを変えたとき
- 重複したとき: 追加しない。リンク欄の下に「この案件には同じリンクの資料がすでにあります: {資料名}」と、その資料を選ぶリンクを出す
- 削除済みの版は比べない。削除済みの版と同じリンクは登録できる

#### 6.0.5 連携の状態の扱い

| 連携の状態 | 画面上の扱い |
|-----------|-------------|
| 未連携 | 連携なし。作成系のボタンと「新しく作る」タブを出さず、連携の案内を出す。資料名と更新日時は自動で取らない |
| 連携中 | 連携あり。作成系のボタンと「新しく作る」タブを出す。資料名と更新日時を自動で取る |
| 要再連携 | 連携ありとしてボタンとタブを出す。押すと「ドライブ連携の有効期限が切れました」と「連携設定へ」を出す。資料名と更新日時の自動取得はしない。要再連携の帯を出す |

- 連携中から要再連携に切り替える条件: ドライブを使う処理(自動取得・作成・コピー)で Google が認可エラーを返したとき

#### 6.0.6 同時操作

- 編集は後勝ちにする(後から保存した内容が残る)
- 版番号の採番、リンクの重複の確認、オーナーが1人以上・管理者が1人以上の確認は、保存と同じ処理の中で行う。2人が同時に操作しても、版番号が重なったり、オーナー・管理者が0人になったりしない。後から処理された側は「入力の問題」として理由を返す

#### 6.0.7 ログインしていないとき・セッションが切れたとき

- 未ログインで認証の要る画面の URL を開いた: ログイン画面へ送り、ログインした後で元の URL へ戻す
- 操作中にセッションが切れた: 次の操作でログイン画面へ送る。入力中の内容は破棄する。ログインした後は元の画面へ戻す
- セッションの有効期限は Phase 3 で決める

#### 構成要素

案件ヘッダー:

- 「← ホーム」: ホームへ戻る
- 案件名と自分の役割(オーナー / 編集者 / 閲覧者)のバッジ
- 「メンバー n人」: メンバー管理(U3)へ。全役割に表示。モバイルでは出さない
- 「+ 資料を追加」: 資料を追加ダイアログ(6.2)を開く。編集者以上・デスクトップとタブレットだけに表示
- 「⋯」メニュー: オーナー・デスクトップとタブレットだけに表示。「案件名を変更」「案件を削除」

ツールバー:

- 資料名の絞り込み欄: 入力するたびに表を絞る(入力が止まってから反映)。系列内の削除されていない版のどれかの名前に部分一致すれば、その系列の行を出す。大文字・小文字、全角・半角の英数字は区別しない
- 種別フィルタ: すべて / ドキュメント / スライド / スプレッドシート / PDF / その他。最新版の種別で判定する
- 件数: 絞り込み後の行数(系列数)

表:

- 1行は1系列の最新版
- 列: 資料名(先頭に種別アイコン、名前の後ろに旧版があれば「旧版 n件」)、種別、更新、登録した人(最新版を登録した人)
- 更新: 最新版の更新日時(7章「導出する値」の「版の更新日時」)
- 並び順: 既定は更新の新しい順。「資料名」「更新」の列見出しを押すと、その列で並べ替え、もう一度押すと逆順
- 行を押す: その系列を選び、横パネルを開いて最新版を表示する。選んだ行は青の背景で示す
- 行にマウスを載せる: 行の右端に「開く ↗」アイコンを出す。押すと最新版のリンクを別タブで開く(横パネルは開かない)
- 「旧版 n件」を押す: その系列を選び、横パネルを開いて版の欄までスクロールする
- 停止された利用者が登録した資料も、登録した人の名前をそのまま表示する

横パネル(選んだ系列の、選んだ版を表示する):

- 見出し: 種別アイコン、選んだ版の資料名、閉じる「×」
- 「開く ↗」: 選んだ版のリンクを別タブで開く
- 概要: 種別、版番号(最新版には「最新」)、更新日時(日時の書式)、登録した人
- 版: 系列の削除されていない版を新しい順に並べる。各行は版番号・資料名・更新日時・登録した人。押すとパネルの表示がその版に切り替わる(表の行は系列のまま)
- 参考資料: 選んだ版の参考資料を並べる。表示のしかたは下の「関連資料の表示規則」に従う。相手が最新版でなければ「v2」などを添える
- この資料を参考にした資料: 系列のどれかの版を参考資料にしている資料を、相手の系列ごとに1行にまとめて並べる。行には相手の系列の最新版の名前を出し、「v2 を参考」のように、この系列のどの版を参考にしたかを添える(7章「導出する値」)。表示のしかたは「関連資料の表示規則」に従う
- 操作(編集者以上・デスクトップとタブレットだけに表示):
  - 「新しい版を作る」: 連携あり(6.0.5)、かつ系列の最新版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く
  - 「これを元に作る」: 連携あり、かつ選んだ版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く
  - 未連携の人には、上の2つの代わりに「ドライブと連携すると、ここから新しい版や資料を作れます(連携設定へ)」という案内を1行出す。資料がドキュメント・スライド以外なら案内も出さない
  - 「新しい版を登録」: 新しい版を登録ダイアログ(6.5.5)を開く。系列の最新版の次の版になる
  - 「登録内容を編集」: 登録内容を編集ダイアログ(6.5.6)を開く
  - 「この版を削除」: 確認ダイアログ「『{資料名}』(v{n})を削除します。アプリの記録から消えます。元の場所にあるファイルは消えません。」の後、選んだ版を削除済みにする

版を削除した後:

| 削除した版 | その後の表示 |
|-----------|-------------|
| 旧版 | 横パネルは系列の最新版を表示する。表の「旧版 n件」を1減らす |
| 最新版(旧版が残っている) | 1つ前の版が最新版になる。表の行と横パネルはその版を表示する |
| 系列の最後の1版 | 表から行を消し、横パネルを閉じる。「資料を削除しました」と通知する |

関連資料の表示規則(参考資料・この資料を参考にした資料で共通)。上から順に判定し、最初に当てはまった表示にする:

| 順 | 相手の資料の状態 | 表示 | 押したとき |
|----|-----------------|------|-----------|
| 1 | 相手の版が削除済み、または相手の案件が削除済み | 「削除された資料」。名前は出さない | 押せない |
| 2 | 相手の案件に自分が参加していない | 鍵アイコン + 「見る権限のない資料」。名前も案件名も出さない | 押せない |
| 3 | 同じ案件の資料 | 種別アイコン + 資料名 | 横パネルがその資料(その版)に切り替わり、表のその行を選ぶ |
| 4 | 自分が参加している他の案件の資料 | 種別アイコン + 資料名 + 「(案件名)」 | その案件の案件画面へ移動し、その資料(その版)を選んだ状態で開く |

- 「この資料を参考にした資料」で、相手の系列の最新版が参考資料を持たず、旧版だけが持っている場合も1行として出す。相手の系列の削除されていない版がどれも参考にしていなければ出さない

#### ユーザー操作とシステムの応答

| 操作 | 応答 |
|------|------|
| 案件画面を開く | 表を読み込む。連携中の人が開いた場合は、あわせて Google の資料の名前と更新日時を裏で取り直す(下の「メタデータの取り直し」) |
| 絞り込み・種別フィルタ | 表をその場で絞る。選んだ系列が条件から外れても、横パネルは開いたまま |
| 行を選ぶ | 横パネルを開く(開いていれば中身を差し替える)。URL にも選んだ系列と版を反映し、再読み込みや共有しても同じ状態で開く |
| 「×」・Esc キー | 横パネルを閉じ、表を全幅に戻す |
| 案件名を変更(オーナー) | 案件名を変更ダイアログ。入力規則は 6.0.3。保存すると見出しとホームの一覧に反映 |
| 案件を削除(オーナー) | 確認ダイアログ「『{案件名}』を削除します。資料の記録は一覧と検索から消えます。元の場所にあるファイルは消えません。」→ 削除するとホームへ戻り、「案件を削除しました」と通知する |
| 失敗したとき | 6.0.2 に従う |

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 読み込み中 | 案件ヘッダーとツールバーは先に出し、表は灰色の仮の行を8行出す |
| 資料が0件(編集者以上・デスクトップとタブレット) | 表の場所に「まだ資料がありません」と「+ 資料を追加」ボタン、「リンクを貼るだけで登録できます」の補足 |
| 資料が0件(閲覧者、またはモバイル) | 「まだ資料がありません。編集者が資料を追加すると、ここに並びます。」(ボタンは出さない) |
| 絞り込みで0件 | 「条件に合う資料がありません」と「絞り込みを解除」ボタン |
| 表の読み込み失敗 | 表の場所に「資料を読み込めませんでした」と「再読み込み」ボタン |
| 案件が無い・参加していない・削除済み | 画面全体に「この案件は見つからないか、参加していません」と「ホームへ」ボタン。どの理由かは区別しない |
| 横パネルの読み込み中 | 見出しと「開く」は表の行の情報で先に出し、版・参考資料・参考にした資料の欄は灰色の仮の行を2行ずつ出す |
| 横パネルの読み込み失敗 | 版・参考資料・参考にした資料の欄の代わりに「読み込めませんでした」と「再読み込み」 |
| 横パネルの版・参考資料・参考にした資料が0件 | その欄に「なし」と表示する(欄は消さない) |
| URL で指定された系列・版が無い・削除済み | 横パネルは開かず、表だけを出す。「この資料は削除されたか、見つかりません」と通知する |
| 削除の処理中 | 確認ダイアログの「削除」ボタンを読み込み中にする |
| メタデータの取り直しの失敗 | 何も表示しない。保存済みの名前と更新日時をそのまま出す(認可エラーなら要再連携に切り替える) |

#### メタデータの取り直し

- 対象: 連携中の人が案件画面を開いたとき、表に並ぶ最新版のうち Google の資料(ドキュメント・スライド・スプレッドシート)
- 取るもの: 元の場所での資料名と更新日時
- 反映: 資料名と更新日時を元の場所の値で上書きし、metadata_fetched_at を記録する。値が変わっていれば表と横パネルに反映する。更新日時が変わったときは案件の最終更新も進める(7章)
- 見られない資料: その人のドライブ権限で見られない資料は取り直さず、保存済みの値のまま
- 未連携・要再連携の人が開いたとき: 取り直さない

### 6.4 ホーム(U1)

以下の画面例は 8章のデモデータで山田がログインした場合の表示。

#### レイアウト構造

```
┌───────────────────────────────────────────────────────────────────┐
│ weaponx                                                     (ユーザー) │
├───────────────────────────────────────────────────────────────────┤
│ 案件                                                               │

└───────────────────────────────────────────────────────────────────┘
```

検索中(案件一覧の場所に結果を出す):

```
│ [🔍 提案書                                     ×] [+ 案件を作る]     │
├───────────────────────────────────────────────────────────────────┤
│ 「提案書」の検索結果 4件                                               │
│ 資料名                     案件             種別        更新           │
```

#### 仕様

案件一覧:

- 参加している、削除されていない案件を並べる。列は案件名・自分の役割・資料数・最終更新(7章「導出する値」)
- 並び順は最終更新の新しい順。行を押すと案件画面へ
- 「+ 案件を作る」(デスクトップとタブレットだけ): 案件を作るダイアログ。案件名は 6.0.3。作成すると自分がオーナーの案件ができ、その案件画面へ移る。作成中・入力の不備・失敗は 6.0 に従う

横断検索:

- 検索欄に1文字以上入れると、入力が止まってから検索し、案件一覧の場所に結果を出す。「×」か検索欄を空にすると案件一覧に戻る

- 結果の1行は一致した版。旧版に一致した場合は「旧版」を添える。列は資料名・案件名・種別・更新(その版の更新日時)。並び順は更新の新しい順
- 行を押す: その案件の案件画面へ移り、その系列を選んで横パネルを開き、一致した版を表示する
- 行にマウスを載せると「開く ↗」アイコンを出す(その版のリンクを別タブで開く)
- 最大50件まで出す。それを超えるときは末尾に「50件以上あります。語を足して絞り込んでください。」

| 状態 | 表示 |
|------|------|
| 読み込み中 | 表に灰色の仮の行を5行 |
| 参加している案件が0件(デスクトップとタブレット) | 「まだ参加している案件がありません」「+ 案件を作る」ボタン、「招待されると、ここに案件が表示されます」の補足 |
| 参加している案件が0件(モバイル) | 「まだ参加している案件がありません」と「招待されると、ここに案件が表示されます」(ボタンは出さない) |
| 検索中 | 結果の表に灰色の仮の行を3行 |
| 検索結果が0件 | 「『{語}』に一致する資料はありません」 |
| 読み込み・検索の失敗 | 「読み込めませんでした」と「再読み込み」ボタン |

#### 6.5.2 メンバー管理(U3)

山田(A社 DX提案の唯一のオーナー)が開いた場合の表示:

```
│ ← A社 DX提案   メンバー                              [+ メンバーを招待] │
│ 名前               メール               役割           追加日            │
│ 山田 太郎(自分)    yamada@example.com   [オーナー ▾]※  2026/09/01  [外す]※│
│ 佐藤 花子           sato@example.com     [編集者 ▾]     2026/09/03  [外す] │
│ 鈴木 一郎(停止中)   suzuki@example.com   [閲覧者 ▾]     2026/09/05  [外す] │
│ ※ 無効: オーナーが1人以上必要です                                        │
```

- 「← {案件名}」: 案件画面へ戻る
- オーナー: 役割をプルダウンで変更でき(オーナー / 編集者 / 閲覧者)、選んだ時点で保存する。「外す」でメンバーから外せる(確認ダイアログあり)。自分を外すこともできる
- 自分の役割をオーナーより下げる: 確認ダイアログ「自分の役割を{役割}に変えると、メンバーの管理ができなくなります。」の後に保存し、表を読み取り専用の表示に切り替える
- 最後のオーナー: その行の役割変更と「外す」は無効化し、「オーナーが1人以上必要です」と添える
- オーナー以外: 同じ表を読み取り専用で表示する。「メンバーを招待」「外す」は出さず、役割はプルダウンでなく文字で出す
- 名前の表示: 停止中の利用者は名前の後ろに「(停止中)」を添える。まだログインしていない利用者は名前の欄に「(未ログイン)」と出す
- 並び順: オーナー、編集者、閲覧者の順。同じ役割の中は名前順
- メンバーを招待ダイアログ: 名前かメールで、有効な利用者のうち、まだメンバーでない人を検索して選ぶ。役割を選ぶ(オーナー / 編集者 / 閲覧者、初期値は編集者)。「招待」でメンバーに加わり、その人の次のログイン以降、ホームに案件が現れる。通知メールは送らない
- 招待の候補が0件: 「該当する利用者がいません。利用者の追加は管理者に依頼してください。」
- 自分を外したとき: ホームへ戻る
- 読み込み中: 表に灰色の仮の行を4行。読み込み失敗: 「読み込めませんでした」と「再読み込み」
- 案件に参加していない・案件が無い: 案件画面と同じ「見つからない」表示
- 操作中・成功・失敗: 6.0 に従う

#### 6.5.3 連携設定(U4)

| 連携の状態 | 表示と操作 |
|-----------|-----------|
| 読み込み中 | 状態表示の場所に読み込み中の表示 |
| 未連携 | 「ドライブと連携すると、資料名と更新日時を自動で取得し、アプリから Google ドキュメント・スライドを作れます。連携しなくても、リンクで登録すればすべての管理機能を使えます。」と「ドライブと連携する」 |
| 連携中 | 「連携中」、連携した日時、「連携を解除」(確認ダイアログ「ドライブ連携を解除します。登録済みの資料と、アプリで作ったファイルはそのまま残ります。」) |
| 要再連携 | 警告色で「ドライブ連携の有効期限が切れました」と「もう一度連携する」、「連携を解除」 |
| Google の許可画面で取り消した・失敗した | 「連携できませんでした。会社の設定で外部アプリとの連携が制限されている場合があります。」。状態は元のまま |
| 許可画面でログイン中と別の Google アカウントを選んだ | 「ログイン中のアカウント({メール})で連携してください。」。連携しない |
| 必要な権限の一部しか許可されなかった | 「必要な権限がすべて許可されませんでした。もう一度連携し、すべての権限を許可してください。」。連携しない |
| 読み込み失敗 | 「読み込めませんでした」と「再読み込み」 |

- 連携はログインしているのと同じ Google アカウント(google_subject が一致)で行う
- 連携・解除の成功は通知で知らせ、表示を新しい状態に切り替える
- 戻るときはヘッダーのアプリ名からホームへ

- 自分の行の「⋯」は無効化し、「自分自身は変更できません」と添える
- 並び順: 有効な利用者を先に、その中は名前順(未ログインはメール順で末尾)
- 利用者を追加ダイアログ: メールアドレス(1件)と「管理者にする」のチェック。追加した人は「有効」で、まだログインしていなければ名前の欄に「(未ログイン)」
- 停止の確認ダイアログ: 「{メール}を停止します。この人はログインできなくなります。」。この人が唯一のオーナーになっている案件があれば、「この人が唯一のオーナーになっている案件が {n} 件あります。停止すると、その案件ではメンバーの招待・役割の変更・外す、案件名の変更、案件の削除ができなくなります。」を警告色で添える。案件名は出さない
- 停止した人がログイン中なら、次の操作でログイン画面に戻り、停止の表示を出す(6.0.2)
- 入力の不備: 登録済みのメールは「このメールアドレスはすでに登録されています」、形式が違えば「メールアドレスの形式が正しくありません」
- 読み込み中: 表に灰色の仮の行を5行。絞り込みで0件: 「条件に合う利用者がいません」。読み込み失敗: 「読み込めませんでした」と「再読み込み」
- 管理者でない人が開いた: 「この画面を開く権限がありません」と「ホームへ」
- 操作中・成功・失敗: 6.0 に従う

#### 6.5.5 新しい版を登録ダイアログ

- 項目: リンク(必須)、資料名(必須、初期値は最新版の名前)、種別(必須、リンクから判定)、更新日時(任意)、参考資料(初期値は最新版の参考資料を引き継ぐ。外したり足したりできる)
- 参考資料の候補からは、同じ系列の版を除く
- 自動取得・入力の規則・状態の表示は資料を追加ダイアログ(6.2)の「リンクで登録」と同じ。リンクの重複は 6.0.4
- 登録すると系列の次の版になり、表の行と横パネルが新しい版を表示する

#### 6.5.6 登録内容を編集ダイアログ

- 横パネルで選んでいる版の、リンク・種別・資料名・更新日時・参考資料を直す
- Google から資料名を取得済みの版(metadata_fetched_at に値がある版)は、資料名と更新日時を読み取り専用にし、「ドライブの名前を使います。名前はドライブで変更してください。」と添える
- リンクを変えたら種別を判定し直す。連携中で Google の資料なら資料名と更新日時を取り直す。リンクの重複は 6.0.4
- 参考資料の候補からは、同じ系列の版を除く
- 入力の規則・状態の表示は資料を追加ダイアログ(6.2)と同じ

#### 6.5.7 エラー

|------|------|
| 存在しない URL | 「ページが見つかりません」と戻り先のボタン |
| 想定外の障害(画面全体を表示できない) | 「問題が発生しました。時間をおいてもう一度お試しください。」と戻り先のボタン |

- 戻り先: ログイン中なら「ホームへ」、未ログインなら「ログインへ」

### 6.6 モバイルでの動き

モバイル(<768px)では「探して開く」だけを提供する。

| 画面・要素 | モバイルでの扱い |
|-----------|-----------------|
| ホーム | 案件一覧(案件名と最終更新の2列)と横断検索(資料名と更新の2列)。「案件を作る」は出さない |

## 7. データモデル

論理設計。Phase 3 で ORM のスキーマに変換する。Phase 1 の「関連」エンティティは、版を「系列 + 版番号」、参考資料を「参考資料表」の2つに分けて持つ形にした。最新版と旧版の件数を一覧で速く出すため。

### ER図

```
users 1──N project_members N──1 projects
users 1──0..1 drive_connections
projects 1──N document_series 1──N documents
documents 1──N document_references N──1 documents   (参考資料。他案件の資料も指せる)
users 1──N documents                                (登録した人)
```

### テーブル定義

共通: すべての id は UUID。日時はタイムゾーン付き。特に断りがなければ created_at / updated_at を持つ。「監査用」と書いたカラムは MVP の画面では使わず、誰がいつ操作したかを後から追えるように持つ(9章の操作の記録で使う)。

#### users(利用者)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| email | 文字列 | 必須 | Google アカウントのメール。小文字にそろえて保存。一意。初回ログインの照合に使う |
| google_subject | 文字列 | 任意 | Google アカウントの不変の ID。初回ログインで保存し、以降の照合と連携のアカウント確認に使う。一意 |
| display_name | 文字列 | 任意 | 初回ログイン時に Google から取得。未ログインなら空 |
| avatar_url | 文字列 | 任意 | Google のアイコン画像の URL |
| global_role | 列挙 | 必須 | member(一般) / admin(管理者)。既定 member |
| status | 列挙 | 必須 | active(有効) / suspended(停止)。既定 active |
| locale | 列挙 | 任意 | ja / en。空なら 1.2 の決め方に従う |
| last_login_at | 日時 | 任意 | 最終ログイン |
| created_by | UUID | 任意 | 追加した管理者(users.id)。監査用。初期設定で登録した最初の管理者は空 |
| created_at / updated_at | 日時 | 必須 | |

- 規則: global_role が admin で status が active の利用者が常に1人以上いる(6.0.6)

#### drive_connections(ドライブ連携)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| user_id | UUID | 必須 | 主キー兼 users.id への参照。1人1連携 |
| status | 列挙 | 必須 | active(連携中) / needs_reauth(要再連携) |
| credentials | 暗号化した値 | 必須 | Google の認可情報。保存と暗号化の方法は Phase 3 で決める |
| granted_scopes | 文字列の配列 | 必須 | 許可されたドライブの権限の範囲。必要な権限がそろっているかの確認に使う |
| connected_at | 日時 | 必須 | 連携した日時 |
| created_at / updated_at | 日時 | 必須 | |

- 連携を解除したら行を消す。行が無いことを「未連携」とする
- 連携した Google アカウントは users.google_subject と一致することを連携時に確認する(一致しなければ保存しない)

#### projects(案件)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| name | 文字列 | 必須 | 1〜100文字。一意にはしない |
| last_activity_at | 日時 | 必須 | 案件の最終更新。更新する場面は下の規則 |
| created_by | UUID | 必須 | 作成した人(users.id)。監査用 |
| deleted_at | 日時 | 任意 | 削除した日時。値があれば削除済み |
| deleted_by | UUID | 任意 | 削除した人。監査用 |
| created_at / updated_at | 日時 | 必須 | |

- last_activity_at を更新する場面: 案件の作成、案件名の変更、版の登録・作成、登録内容の編集、版の削除、メタデータの取り直しで版の更新日時が新しくなったとき。値はその操作の日時(取り直しの場合は新しい更新日時と今の値の新しいほう)
- 規則: 削除されていない案件には role が owner のメンバーが常に1人以上いる(6.0.6)

#### project_members(案件メンバー)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| project_id | UUID | 必須 | projects.id。主キーの一部 |
| user_id | UUID | 必須 | users.id。主キーの一部 |
| role | 列挙 | 必須 | owner(オーナー) / editor(編集者) / viewer(閲覧者) |
| added_by | UUID | 任意 | 招待した人。監査用。案件の作成者自身の行は空 |
| created_at / updated_at | 日時 | 必須 | created_at をメンバー管理の「追加日」に使う |

#### document_series(資料の系列)

一覧の1行にあたる。同じ資料の版をまとめる。

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| project_id | UUID | 必須 | 属する案件(projects.id) |
| next_version_no | 整数 | 必須 | 次に採番する版番号。1から始め、版を登録するたびに1増やす(削除しても戻さない)。採番は版の保存と同じ処理の中で行う |
| created_at / updated_at | 日時 | 必須 | |

- 削除されていない版が0件の系列は、一覧・検索・資料数・参考にした資料に含めない

#### documents(資料の版)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| series_id | UUID | 必須 | document_series.id |
| version_no | 整数 | 必須 | 系列内の版番号。(series_id, version_no) で一意 |
| name | 文字列 | 必須 | 1〜200文字。Google から取得できた版は元の場所の名前 |
| url | 文字列 | 必須 | http / https、2048文字まで。重複の規則は 6.0.4 |
| kind | 列挙 | 必須 | google_doc / google_slides / google_sheets / pdf / other |
| google_file_id | 文字列 | 任意 | Google の資料なら URL から取り出した ID。重複の判定、メタデータの取り直し、コピーに使う |
| source_modified_at | 日時 | 任意 | 元の場所での更新日時。連携中は自動、それ以外は任意入力(日付のみ) |
| metadata_fetched_at | 日時 | 任意 | 資料名と更新日時を Google から最後に取得した日時。値があれば資料名と更新日時は読み取り専用(6.5.6) |
| created_via | 列挙 | 必須 | link(リンクで登録) / created(新しく作る) / copied(これを元に作る・新しい版を作る)。監査用 |
| registered_by | UUID | 必須 | 登録した人(users.id) |
| deleted_at | 日時 | 任意 | 削除した日時。値があれば削除済み |
| deleted_by | UUID | 任意 | 削除した人。監査用 |
| created_at / updated_at | 日時 | 必須 | created_at を登録日時として使う |

- 削除済みの版には、新しい版の登録(系列が全版削除済みの場合)・登録内容の編集・参考資料としての新たな選択を受け付けない(6.0.2「見つからない」「入力の問題」)

#### document_references(参考資料)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| document_id | UUID | 必須 | 参考資料を持つ側の版(documents.id)。主キーの一部 |
| referenced_document_id | UUID | 必須 | 参考資料の版(documents.id)。他の案件の資料でもよい。主キーの一部 |
| created_by | UUID | 必須 | 記録した人。監査用 |
| created_at | 日時 | 必須 | 行は追加と削除だけで更新しないので updated_at は持たない |

- 規則: 同じ系列の版どうしは参考資料にできない。1つの版の参考資料は20件まで
- 参考資料の版やその案件が削除済みになっても行は残し、表示で「削除された資料」とする(6.1 関連資料の表示規則)

### 導出する値

| 値 | 求め方 |
|----|--------|
| 系列の最新版 | 系列の削除されていない版のうち、version_no が最大のもの |
| 版の更新日時 | その版の source_modified_at。無ければその版の created_at |
| 旧版の件数 | 系列の削除されていない版の数 - 1 |
| 案件の資料数 | 削除されていない版を1件以上持つ系列の数 |
| 案件の最終更新 | projects.last_activity_at |
| 参考資料(ある版の) | document_references で document_id がその版である行の referenced_document_id |
| この資料を参考にした資料(ある系列の) | referenced_document_id がこの系列のいずれかの版で、document_id が削除されていない版である行を集め、document_id の系列ごとに1行にまとめる。行の名前はその系列の最新版の名前。添える版番号は、その系列が参考にしたこの系列の版のうち最大の version_no |
| 唯一のオーナーの案件数 | その人が owner で、他に owner がいない、削除されていない案件の数 |

## 9. 今後の検討事項

### 拡張候補

- 地図表示: 記録した参考資料と版の関連を地図で俯瞰する。資料が増えて一覧で追えなくなったら足す(`docs/concept.md` の「俯瞰できる」体験)
- 読む順・未読の管理: 案件に後から入った人向けに、読むべき資料と順番を示す
- ドライブの共有設定の同期: 案件内の役割に合わせてドライブの共有を揃える。3つの役割とドライブの権限の対応を詰めてから判断する
- スプレッドシートの「これを元に作る」「新しい版を作る」: MVP はドキュメントとスライドだけ。コピーの仕組みは同じなので、要望があれば足す
- ドライブ以外の保存先との連携(Box・OneDrive 等)
- 案件から自分で抜ける操作(オーナー以外)
- 停止された唯一のオーナーの案件の救済(管理者によるオーナーの付け替え等)。MVP は停止時の警告だけ
- 削除済みの案件・資料の復元
- 本文検索: 本文を保存しない方針と引き換えに持たない。必要になったら、本文をどこまで預かるかから決め直す
- 操作の記録(誰がいつ登録・削除したかの履歴画面)。監査用のカラムはこのために持っている
- 招待の通知(メール等)
- 同時編集の検出(後から保存した人に「他の人が変更しました」と知らせる)。MVP は後勝ち
- 一覧のページ分け(想定規模を超えたとき)

### 既知の制約

- 連携なしで登録した資料は、リンク先が更新・移動されてもアプリには伝わらない。最新版の正しさは人の登録に頼る
- 会社の Google Workspace で外部アプリとの連携が制限されている場合、連携機能は使えない。中核の管理機能はリンク登録で使える
- 案件内の役割は資料そのものの閲覧権限を与えない。メンバーが資料を開けるかは元の場所の共有設定しだい
- Google の資料名はアプリ上で変えられない。名前を変えたいときはドライブで変える
