# weaponx — 設計仕様書

> **資料の管理をアプリが引き受け、案件・参考資料・版を作った時点で記録する。資料が増えても「どれが最新で、何を参考にしたか」が一覧で分かる。**

---

## 1. プロダクト概要

### 1.1 コンセプト

案件ごとにスライドとドキュメントが増え続ける職種(コンサル・営業・リサーチ職など)に向けた資料管理ツール。資料が増えると、資料どうしの関連・最新版・読むべきものが分からなくなる。この課題を、散らかった後に推測して見える化するのではなく、資料を作った(登録した)時点で「どの案件か」「何を参考にしたか」「どれの新しい版か」を事実として記録することで解く。

- 対象: 案件ごとに資料が増え続ける人(ターゲットと課題は `docs/01_prd.md` 3章)
- 管理の単位: 案件。資料は1つの案件に属し、案件の中では1行に1系列(同じ資料の版の並び)の最新版が並ぶ
- 関連の種類: 参考資料(この資料を作るときに参考にした資料)と版(同じ資料の新しい版)の2種類。どちらも推測せず、人の記録か、アプリの「これを元に作る」「新しい版を作る」操作で決まる
- 版の意味: 版は別ファイルとして作られた資料を指す。同じファイルを上書き編集しても版は増えず、更新日時が変わるだけ
- 書く・作る道具: 持たない。Google ドキュメント・スライドなど既存の道具を借り、アプリは管理に徹する
- 記録の続け方: 資料はアプリから作る(新しく作る・これを元に作る・新しい版を作る)のが基本。作る操作のついでに参考資料と版が記録されるので、手間なく記録が続く。アプリの価値は記録が続くことにかかっているため、ドライブ連携を前提にする。リンクでの登録は、ドライブ以外の場所にある資料や、使い始める前からある資料のための補助の道
- 版の記録: 版には変更メモ(その版で何を変えたか)とタグ(「提出」など)を付けられる。git のコミットメッセージとタグにあたる。「最新版」と「客先に出した版」の違いが一覧で分かる

経緯: Phase 0 の `docs/concept.md` は「ドライブの資料を後から読んで関連を地図に描く」だった。Phase 1 の壁打ちで上記に見直した(`docs/brainstorm-notes.md` の「コンセプトからの見直し」)。

### 1.2 プロダクト方針

| 項目 | 方針 |
|------|------|
| 用途 | 自分用の MVP。課金なし。同じ職場の人も招待して使える |
| 対応言語 | 日本語と英語。詳細は下の「言語と表示の規則」 |
| 端末 | デスクトップ優先。スマホでは「案件と資料を探して開く」ことだけができる(6.6) |
| ログインとドライブ連携 | Google アカウントでログインする。ログインするときにドライブの許可も一緒にもらい、全員がドライブと連携した状態で使う(連携しないで使う道は無い)。Google アカウントを持たない人は MVP の対象外。会社の Google Workspace のアカウントと個人の Gmail のどちらでも使える |
| ドライブの許可の範囲 | アプリで作ったファイルと、Google のファイル選択画面で選んだファイルだけに効く範囲にする(ドライブ全体は読まない。理由は System Design Doc ADR-011)。アプリがまだ使えないファイルは、ファイル選択画面で選んでもらって使えるようにする(6.0.9) |
| 資料の実体 | 元の場所(ドライブ・Box・社内サーバ等)に置いたまま。アプリはリンクと管理情報だけを持つ |
| 元の場所への作用 | アプリは元の場所のファイルを消さない・書き換えない。例外は、利用者の操作でドライブに新しいファイルを作る(空の資料の作成と、既存資料のコピー)ことだけ |
| Google の資料の名前 | 元の場所から取得できた資料名と更新日時を正とする。アプリ上では書き換えない(名前を変えたいときはドライブで変える) |
| 本文 | 保存しない。関連を推測しないので本文を読む必要がない。検索は資料名だけを対象にする |
| 権限の効き方 | 案件内の役割はアプリ上の管理情報に効く。資料そのものを開けるかは、元の場所の権限に従う。ドライブの共有設定は同期しない |
| 一覧の件数 | MVP の一覧(案件・資料・メンバー・利用者)はページ分けせず全件を出す。想定規模は、1人あたりの参加案件が数十件、1案件の系列が数百件まで。横断検索の結果だけ件数で打ち切る(6.4) |

言語と表示の規則:

- 画面の文言はすべて日本語と英語の2言語で用意する。文言は翻訳ファイルで管理し(形式は `docs/02-01_system-design-doc.md` 9章)、英語の文言は実装で確定する。主な用語の英語は 1.4 に従う
- 翻訳しないもの: 利用者が入力した内容(案件名・資料名など)、元の場所から取得した資料名、Google から取得した表示名、アプリ名 weaponx
- 表示言語の決め方:
  - ログイン前: ブラウザに保存した選択があればそれを、無ければブラウザの言語設定を使う(日本語なら日本語、それ以外は英語)。ログイン画面で切り替えた値はブラウザに保存する
  - ログイン時: 利用者の表示言語の設定が空なら、そのときの表示言語を設定として保存する。設定に値があればそれを使う
  - ログイン後: ユーザーメニューで切り替えると、利用者の設定とブラウザの両方に保存する
- 件数の英語は単数と複数を区別する(1 document / 2 documents)
- 日時の書式(タイムゾーンはブラウザのもの):

| 種類 | 日本語 | 英語 | 使う場所 |
|------|--------|------|---------|
| 日付 | 2026/09/28 | Sep 28, 2026 | 一覧の列、横パネルの版の欄、検索結果、追加日 |
| 日時 | 2026/09/28 14:05 | Sep 28, 2026, 2:05 PM | 最終ログイン、横パネルの概要の更新日時 |

- 名前で並べ替えるときは、表示言語の辞書順に従う

### 1.3 UI設計原則

| 原則 | 内容 |
|------|------|
| 最新版が主役 | 一覧には常に最新版だけを並べる。旧版は求められたときだけ横パネルで見せる。「読むべきなのはこの行」を崩さない |
| 記録は操作のついで | 資料はアプリから作るのを基本の道として一番手前に置く。「これを元に作る」「新しい版を作る」では参考資料と版が自動で記録される。人が手で関連を選ぶのは、資料を登録・編集するときの参考資料欄だけにする |
| 開くまで最短 | 一覧の行にマウスを載せると「開く」アイコンが出て、横パネルを開かずに元の場所へ行ける |
| 使えない操作の見せ方 | 役割・端末・資料の種別で使えない操作のボタンは表示しない。それ以外の条件でできない操作(最後のオーナーを外す、自分自身を停止するなど)は、ボタンを無効化して理由を添える。例外として、要再連携のときの作成系の操作は、再連携へ誘導するため押せるまま出す(6.0.5) |
| 元の場所が正 | 資料の中身・名前・共有は元の場所が決める。アプリは開けない資料を開けるようには見せない。権限のない他案件の資料は「見る権限のない資料」とだけ表示する |
| 高密度で見渡す | 行を詰め、1画面に多くの資料を並べる。装飾より資料名と関連を目立たせる |

### 1.4 用語

画面の文言と仕様書で使う言葉。英語は画面の英語表記に使う。

| 日本語 | 英語 | 意味 |
|--------|------|------|
| 案件 | Project | 資料をまとめる単位。メンバーと役割を持つ |
| 資料 | Document | 元の場所にあるファイルへのリンクと、その管理情報 |
| 版 | Version | 同じ資料の、別ファイルとして作られた各回。v1, v2, … と数える |
| 最新版 | Latest | 系列のうち、削除されていない最大の版 |
| 旧版 | Older versions | 最新版より前の、削除されていない版 |
| 参考資料 | References | この資料を作るときに参考にした資料。スライド巻末に付ける補足資料の意味ではない |
| この資料を参考にした資料 | Referenced by | この資料を参考資料にしている資料 |
| これを元に作る | Create from this | 選んだ資料をコピーして、新しい資料を作る操作 |
| 新しい版を作る | Create new version | 最新版をコピーして、同じ系列の次の版を作る操作 |
| 登録した人 | Added by | その版をアプリに登録した(作った)人 |
| 変更メモ | Change note | その版で何を変えたかを書く1行のメモ。git のコミットメッセージにあたる |
| タグ | Tag | 版に付ける短い印(例: 提出、確定)。git のタグにあたる。同じ系列の複数の版に同じタグを付けてもよい |
| 横パネル | (画面には出さない) | 案件画面で資料を選んだときに右側に開く欄 |
| 要再連携 | Reconnection needed | ドライブの許可が切れた状態(Google アカウント側で許可を取り消した、期限が切れた等)。画面の文言は「ドライブ連携の有効期限が切れました」 |
| Google の資料 | (画面には出さない) | ドライブにあるファイルの資料。ドキュメント・スライド・スプレッドシートと、ドライブに置いた PDF などのファイル。資料名と更新日時を元の場所から取れる |
| 系列 | (画面には出さない) | 同じ資料の版の並び。一覧の1行にあたる。仕様書とデータモデルだけで使う |

## 2. ユーザーロールとフロー

### 2.1 ロール定義

全体のロール(アプリ全体で1人に1つ):

| ロール | 概要 | 主な操作 |
|--------|------|----------|
| 一般ユーザー | 管理者に許可された Google アカウントで入り、案件と資料を管理する人 | 案件の作成、参加している案件での役割に応じた操作、横断検索、表示言語の切り替え |
| 管理者 | 使える人を管理する人 | 一般ユーザーの操作 + 利用者の追加・停止・再開、管理者の付与・解除 |

案件内の役割(案件ごとに1人に1つ):

| 役割 | 概要 | 主な操作 |
|------|------|----------|
| オーナー | 案件の責任者。複数置ける | 編集者の操作 + メンバーの招待・役割の変更・外す、案件名の変更、案件の削除 |
| 編集者 | 案件の資料を管理する人 | 閲覧者の操作 + 新しく作る・これを元に作る・新しい版を作る、リンクでの資料の追加・新しい版の登録、登録内容(変更メモ・タグを含む)の編集、版の削除 |
| 閲覧者 | 案件の資料を見るだけの人 | 資料一覧・関連・版の閲覧、資料を開く、メンバー一覧の閲覧 |

権限の規則:

- 管理者でも、参加していない案件の案件名・資料・メンバーは見られない。例外は、停止の確認画面に出す「唯一のオーナーになっている案件の件数」だけ
- 案件の作成者は、その案件の最初のオーナーになる
- 削除されていない案件には、オーナーが常に1人以上いる。最後のオーナーは、自分を外すことも自分の役割を変えることもできない
- 管理者は常に1人以上いる。管理者は自分自身を停止することも、自分の管理者を外すこともできない
- 停止された利用者はログインできない。案件での役割・登録した資料・登録した人としての名前表示は残る
- 役割が変わった・メンバーから外された・停止されたときは、その人の次の操作から反映する(6.0.2)
- 最初の管理者は初期設定で登録する(手順は `docs/04_deployment-procedure.md`)

### 2.2 フロー全体像

```
全員(探して開く・コアフロー):
  ログイン → ホーム(案件一覧) → 案件 → 資料を選ぶ → 横パネルで参考資料・版・参考にした資料をたどる → 開く(別タブ)

全員(横断で探す):
  ホーム → 検索欄に資料名を入力 → 結果の資料を選ぶ → 案件(その資料を選んだ状態) → 開く(別タブ)

編集者以上(作る・基本の道):
  新しく作る:     案件 → 資料を追加 → 新しく作る → 種別・名前・参考資料を入力 → 一覧に並び、編集画面が別タブで開く
  これを元に作る: 案件 → 資料を選ぶ → これを元に作る → 名前・追加先を確認 → 編集画面が別タブで開く(参考資料は自動で記録)
  新しい版を作る: 案件 → 資料を選ぶ → 新しい版を作る → 名前・変更メモを入力 → 編集画面が別タブで開く(版は自動で記録)

編集者以上(リンクで登録する・補助の道):
  資料を追加:     案件 → 資料を追加 → リンクで登録 → リンクを貼る → 名前・種別・参考資料を入力 → 一覧に並ぶ
  新しい版を登録: 案件 → 資料を選ぶ → 新しい版を登録 → リンクを貼り、変更メモを入力 → 系列の最新版になる

編集者以上(タグを付ける):
  案件 → 資料を選ぶ → 版を選ぶ → 登録内容を編集 → タグを入力(例: 提出) → 一覧の行と版の欄にタグが出る

オーナー:
  案件 → メンバー → 招待・役割の変更・外す

管理者:
  ユーザーメニュー → 利用者管理 → 利用者の追加・停止・再開、管理者の付与・解除
```

## 3. 画面一覧

画面の存在・目的・レイアウト・認証要否はこのドキュメントが所有する。レイアウトパターン(P1〜P3)の定義は 4.1 を参照。

### 3.1 共通画面

| 画面名 | 目的 | 説明 | レイアウト | 認証 |
|--------|------|------|-----------|------|
| ログイン | 利用を始める | Google アカウントでログインし、同時にドライブの許可を与える。許可されていない・停止されたアカウントや、ドライブの許可が足りない場合は理由を表示する。ログイン前でも表示言語を切り替えられる | P1 中央集中 | 不要 |
| エラー | 開けないページを知らせる | 存在しない URL(ページが見つかりません)と、想定外の障害(問題が発生しました)を表示し、戻り先を出す | P1 中央集中 | 不要 |

### 3.2 一般ユーザー面(管理者も使う)

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| U1 | ホーム | 案件を選ぶ・作る、資料を横断で探す | 参加している案件の一覧と「案件を作る」。検索欄に入力すると、参加している全案件の資料を資料名で検索し、案件一覧の場所に結果を出す | P3 一覧 | 要 |
| U2 | 案件 | 資料を探して開く(コア画面) | 資料を表形式で並べる。1行は1系列の最新版。資料を選ぶと右に横パネルが開き、版・参考資料・参考にした資料と操作を出す | P2 一覧 + 横パネル | 要(案件のメンバーのみ) |
| U3 | メンバー管理 | 案件の参加者を管理する | 案件のメンバー一覧。オーナーは招待・役割の変更・外すができる。他の役割は閲覧だけ | P3 一覧 | 要(案件のメンバーのみ) |

ドライブ連携の設定画面は持たない。連携はログインのときに行い、許可が切れたときは要再連携の帯から直接 Google の許可画面を開く(6.0.5)。

### 3.3 管理者面

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| A1 | 利用者管理 | 使える人を管理する | 利用者の一覧。追加・停止・再開・管理者の付与と解除 | P3 一覧 | 要(管理者のみ) |

### 3.4 ダイアログ一覧

画面ではなく、画面の上に重ねて開くダイアログ(パターン D)。

| ダイアログ | 開く場所 | 目的 | 対象 |
|-----------|---------|------|------|
| 案件を作る | ホーム | 案件名を入れて案件を作る | 全員 |
| 資料を追加 | 案件 | 新しく作る(既定のタブ)か、リンクで登録する | 編集者以上 |
| 新しい版を登録 | 案件(横パネル) | リンクを貼って系列の新しい版として登録する。変更メモを書ける | 編集者以上 |
| 作成(これを元に作る / 新しい版を作る) | 案件(横パネル) | 選んだ資料をコピーして新しい資料・新しい版を作る。新しい版では変更メモを書ける | 編集者以上 |
| 登録内容を編集 | 案件(横パネル) | 選んだ版のリンク・種別・参考資料・変更メモ・タグを直す。資料名と更新日時は、Google から取得済みでなければ直せる(6.5.6) | 編集者以上 |
| 案件名を変更 | 案件 | 案件名を直す | オーナー |
| メンバーを招待 | メンバー管理 | 許可済みの利用者を選び、役割を決めて招待する | オーナー |
| 利用者を追加 | 利用者管理 | 利用を許可する Google アカウントを追加する | 管理者 |
| 確認ダイアログ | 各画面 | 版・案件の削除、メンバーを外す、自分の役割を下げる、利用者の停止など、取り消しにくい操作の前に確認する | 操作できる人 |

### 3.5 ログイン・エラー以外の全画面に共通の要素

- ヘッダー: 左にアプリ名 weaponx(押すとホーム)。右にユーザーアイコン。アイコンを押すとユーザーメニューが開く
- ユーザーメニュー: 表示言語(日本語 / English)、利用者管理(管理者にだけ表示)、ログアウト。モバイルでは利用者管理を出さない
- 要再連携の帯: ドライブ連携が要再連携のとき、ヘッダーの下に警告色で「ドライブ連携の有効期限が切れました」と「もう一度連携する」を表示する。押すと Google の許可画面を開く(6.0.5)。モバイルでは出さない
- 通知: 画面上部に数秒出て消える通知(成功・失敗の知らせ)。失敗の通知は自分で閉じるまで残す

## 4. デザインシステム

### 4.1 レイアウトパターン定義

| パターン | 形 | 使う場面 |
|---------|-----|---------|
| P1 中央集中 | 画面中央に1枚のカード。ヘッダーなし | ログイン前や、開けないページを知らせる、1つの操作だけに注目させる画面 |
| P2 一覧 + 横パネル | 上にツールバー、下に全幅の表。行を選ぶと右側に横パネルが開き、表の幅が縮む。閉じると全幅に戻る | 一覧を見ながら、選んだ1件の詳細と関連をたどる画面 |
| P3 一覧 | 上にページ見出しとツールバー(検索欄・主操作ボタン)、下に全幅の表 | 同じ種類のものを並べて選ぶ・管理する画面 |

## 6. コア画面詳細仕様

### 6.0 全画面に共通の規則

各画面の仕様に書いていない場合は、この規則に従う。

#### 6.0.1 読み込み・操作中・成功

| 場面 | 表示 |
|------|------|
| 画面・表の読み込み中 | 見出しとツールバーを先に出し、表は灰色の仮の行を出す(行数は各画面の仕様) |
| ボタンの操作中 | 押したボタンを読み込み中の表示にし、同じボタンを押せなくする。ダイアログは閉じない |
| 操作の成功 | 通知で知らせる(例:「資料を追加しました」「役割を変更しました」)。画面の表示を最新の状態に更新する |

#### 6.0.2 失敗の分類と振る舞い

サーバーから返る失敗を次の5つに分け、画面ごとに同じ振る舞いをする。

| 分類 | 起きる例 | 文言 | 画面の動き |
|------|---------|------|-----------|
| 見つからない | 選んでいた版・系列・案件が他の人に削除された。自分が案件のメンバーから外された。削除されていない版が1つも無い系列に新しい版を登録しようとした。削除済みの版を編集しようとした。操作しようとしたメンバーがすでに外されていた | 資料:「この資料は削除されたか、見つかりません」。案件:「この案件は見つからないか、参加していません」。メンバー:「このメンバーはすでに外されています」 | ダイアログを閉じ、表を読み込み直す。横パネルで開いていた版だけが無くなり系列が残っていれば、横パネルを系列の最新版に切り替える。系列が無くなったら横パネルを閉じる。案件が無くなった・外された場合は案件画面全体を「見つからない」表示にする(理由は区別しない) |
| 権限がない | 案件のメンバーのまま役割が足りなくなった。管理者を外された。停止された | 役割:「役割が変更されたため、この操作はできません」。管理者:「この画面を開く権限がありません」。停止: 通知は出さない | ダイアログを閉じる。役割が下がった場合は画面を読み込み直し、新しい役割に合わせてボタンを出し直す。管理者を外された場合は利用者管理(A1)を 6.5.4 の「この画面を開く権限がありません」表示に切り替える。停止された場合はログイン画面へ送り、ログイン画面の停止の表示だけを出す |
| 入力の問題 | 検証エラー(6.0.3)、リンクの重複(6.0.4)、新しく選んだ参考資料が削除された・見られなくなった、招待しようとした人が停止された・すでにメンバーになっていた、最後のオーナー・最後の管理者を外そうとした、作成の追加先の案件に追加できなくなった | 「参考資料『{資料名}』は削除されたか見られなくなったため外しました」「{名前}さんは停止されているため招待できません」「{名前}さんはすでにメンバーです」「オーナーが1人以上必要です」「管理者が1人以上必要です」「この案件には追加できません」。検証エラーとリンクの重複の文言は 6.0.3・6.0.4 | ダイアログは閉じず、入力を保つ。該当する欄の下に理由を出す。該当する参考資料のチップは外す。すでにメンバーだった場合は表を読み直す。入力欄の無い操作(役割のプルダウン、確認ダイアログだけの操作)は失敗の通知で理由を出し、プルダウンは元の値に戻して表を読み直す |
| 要再連携 | ドライブの操作で Google が認可エラーを返した | 「ドライブ連携の有効期限が切れました」と「もう一度連携する」 | ダイアログは閉じず、入力を保つ。連携の状態を要再連携に切り替える。「もう一度連携する」を押すと Google の許可画面へ移り、戻ると元の画面を開き直す(ダイアログの入力は保たない)。詳細は 6.0.5 |
| 通信・その他 | ネットワークの切断、サーバーの障害 | 「保存できませんでした。もう一度お試しください」(読み込みなら「読み込めませんでした」と「再読み込み」) | ダイアログは閉じず、入力を保つ |

#### 6.0.3 入力の共通規則

- 文字列は前後の空白を取り除いてから検証する。空白だけの入力は空とみなす。改行は受け付けない(1行入力)
- 文字数は見た目の1文字を1と数える
- 上限: 案件名 100文字、資料名 200文字、リンク 2048文字、検索語 100文字、変更メモ 100文字、タグ 20文字、1つの版の参考資料 20件、1つの版のタグ 5件、入力欄の候補(参考資料・招待する人・タグ)の表示 20件(超えるときは語を足して絞り込んでもらう)
- 検証エラーは欄の下に理由を出し、確定ボタン(追加・作成・保存・招待)を押せなくする
- 文言の例: 「入力してください」「{n}文字以内で入力してください」「http または https で始まるリンクを入力してください」「参考資料は20件まで選べます」「タグは5件まで付けられます」
- タグの重複: 1つの版に同じタグは付けられない(大文字・小文字、全角・半角の英数字は区別しない)。入力すると無視して、既存のチップを光らせる
- タグの入力: 5件になったら入力欄を無効にし、「タグは5件まで付けられます」と添える。確定していない入力(Enter の前の文字)が残ったまま保存したときは、確定してから検証する。候補を読み込めなくても自由に入力できる
- 参考資料の検証: 保存時に確かめるのは、そのダイアログで新しく足した参考資料だけ(削除されていないか、自分が参加している案件の資料か)。すでに記録されている参考資料と、前の版から引き継いだ参考資料は、削除済みや見られない資料を含んでいてもそのまま受け付ける。ダイアログのチップは 6.1 の「関連資料の表示規則」に従って表示し(名前を出さないものも含む)、×で外せる

#### 6.0.4 リンクの重複

- 同じ案件の中で、削除されていない版どうしは同じリンクを持てない。別の案件に同じリンクがあるのは許す
- 比べ方: Google の資料は URL から取り出したファイル ID で比べる。それ以外は前後の空白を除いた URL の文字列で比べる
- 確認する操作: 資料の追加、新しい版の登録、登録内容の編集でリンクを変えたとき
- 重複したとき: 追加しない。リンク欄の下に「この案件には同じリンクの資料がすでにあります: {資料名}」と、その資料を選ぶリンクを出す
- 削除済みの版は比べない。削除済みの版と同じリンクは登録できる

#### 6.0.5 ドライブ連携の状態の扱い

連携はログインのときに行う(6.5.1)。ログインした利用者は、連携中か要再連携のどちらかの状態にある。

| 連携の状態 | 画面上の扱い |
|-----------|-------------|
| 連携中 | 作成系の操作(新しく作る・これを元に作る・新しい版を作る)を出す。Google の資料の名前と更新日時を自動で取る |
| 要再連携 | 作成系の操作のボタン(新しい版を作る・これを元に作る・資料を追加)はそのまま出す(1.3 の例外)。作成ダイアログや資料を追加の「新しく作る」タブを開いた時点で、上部に「ドライブ連携の有効期限が切れました」と「もう一度連携する」を出し、「作成」を押せなくする(入力を始める前に分かるようにする)。資料を追加は「リンクで登録」タブを既定で開く。資料名と更新日時の自動取得はしない。要再連携の帯を出す(3.5) |

- 要再連携に切り替える条件: ドライブを使う処理(自動取得・作成・コピー)で Google が認可エラーを返したとき
- 認可エラー: アプリの認可情報が無効・取り消された・期限切れ、または必要な許可の範囲が足りないときの Google の応答。資料ごとの拒否(その資料を見る権限がない、元の資料が消えている等)は認可エラーに含めず、要再連携にしない
- もう一度連携する: 帯または失敗の表示の「もう一度連携する」で Google の許可画面を開く。戻ってきたときの表示は下の表。どの場合も元の画面に戻る

| 許可画面での結果 | 表示 |
|-----------------|------|
| 許可された | 「ドライブに再連携しました」と通知し、帯を消す。連携中に戻る |
| 取り消した・Google 側で拒否された | 「連携できませんでした。許可を取り消した場合はもう一度お試しください。会社の設定で外部アプリとの連携が制限されている場合は利用できません。」と通知。要再連携のまま |
| 通信・その他の失敗(戻った後の保存の失敗など) | 「連携できませんでした。もう一度お試しください。」と通知。要再連携のまま |
| ログイン中と別の Google アカウントを選んだ | 「ログイン中のアカウント({メール})で連携してください。」と通知。要再連携のまま |
| 必要な権限の一部しか許可されなかった | 「必要な権限がすべて許可されませんでした。もう一度連携し、すべての権限を許可してください。」と通知。要再連携のまま |

- 連携の解除はアプリに持たない。Google アカウントの設定で許可を取り消すと、次にドライブを使う処理で要再連携になる

#### 6.0.6 同時操作

- 編集は後勝ちにする(後から保存した内容が残る)。タグは、保存するとその版のタグがダイアログで入力した一式になる(同時に別の人が足したタグとは合わせない)ので、5件の上限と重複の確認は保存と同じ処理の中で行う
- 版番号の採番、リンクの重複の確認、オーナーが1人以上・管理者が1人以上の確認は、保存と同じ処理の中で行う。2人が同時に操作しても、版番号が重なったり、オーナー・管理者が0人になったりしない
- 版番号: 2人が同時に新しい版を登録・作成したら、後から処理された側は次の番号で成功する(失敗にしない)。「新しい版を作る」のコピー元はダイアログを開いたときの最新版で、番号は処理した時点の系列の次の番号になる
- リンクの重複・最後のオーナー・最後の管理者: 後から処理された側に「入力の問題」を返す
- 同じ結果になる操作: すでに停止されている人の停止、有効な人の再開、すでにその役割の人への役割の変更は、成功として扱う

#### 6.0.7 ログインしていないとき・セッションが切れたとき

- 未ログインで認証の要る画面の URL を開いた: ログイン画面へ送り、ログインした後で元の URL へ戻す
- 操作中にセッションが切れた: 次の操作でログイン画面へ送る。入力中の内容は破棄する。ログインした後は元の画面へ戻す
- セッションの有効期限は `docs/02-01_system-design-doc.md` が決める

#### 6.0.8 ドライブでの作成を伴う操作

「新しく作る」「これを元に作る」「新しい版を作る」は、アプリの確認 → ドライブでの作成 → アプリへの登録の順に行う。

- アプリの確認(ドライブで作成する前): 連携の状態(要再連携なら Google を呼ばずに 6.0.2「要再連携」を返す)、案件・系列が削除されていないか、自分の役割が足りるか、追加先の案件に追加できるか、入力に不備がないか。ここで失敗したら、ドライブには何も作らず 6.0.2 に従う。ただし「これを元に作る」の追加先の案件が削除された・自分の役割が編集者より下になった場合は「入力の問題」とし、追加先の欄の下に「この案件には追加できません」と出して候補を読み直す(今の案件画面は「見つからない」表示にしない)
- ドライブでの作成に失敗: 「ドライブに資料を作れませんでした。もう一度お試しください。」(要再連携なら 6.0.2)。元の資料が見つからない・開けない場合は「元の資料が見つからないか、開く権限がないため、コピーできません。」
- ドライブには作成できたが、アプリへの登録に失敗:
  - 通信・その他の失敗: 「ドライブに資料は作成されましたが、登録できませんでした。」と、作成したファイルを開くリンク、「このリンクで登録」ボタン(新しく作る・これを元に作るなら資料を追加ダイアログ、新しい版を作るなら新しい版を登録ダイアログを、そのリンクと、入力済みの資料名・参考資料・変更メモを入れて開く)
  - 見つからない・権限がない(確認の後、登録までの間に変わった): 「ドライブに資料は作成されましたが、登録できませんでした。」と、作成したファイルを開くリンクだけを出す(「このリンクで登録」は出さない)。そのうえで 6.0.2 の画面の動きに従う
- 作成したファイルはどの場合もドライブに残り、アプリは消さない
- 作成したファイルの置き場所: 作成した人のマイドライブ直下(フォルダは作らない)。置き場所と共有設定は、利用者がドライブで変える。移動してもファイル ID は変わらないので、アプリの記録はそのまま使える

#### 6.0.9 アプリが使えるドライブのファイル

アプリがドライブで読んだりコピーしたりできるのは、その人がアプリで作ったファイルと、その人が Google のファイル選択画面で選んだファイルだけ(1.2「ドライブの許可の範囲」)。ほかの人が登録した資料や、リンクを貼っただけの資料は、まだ使えないことがある。

- 使えない資料に、資料名の自動取得・コピーが要る場面では、「このファイルをアプリで使えるようにする」ボタンと、「ドライブのファイル選択画面で選ぶと、アプリで資料名を読んだりコピーしたりできます。」を出す
- ボタンを押すと、Google のファイル選択画面をその1ファイルだけを見せた状態で開く。選ぶと使えるようになり、元の操作(自動取得・コピーの前の確認)をやり直す。ダイアログの入力は保つ
- ファイル選択画面にそのファイルが出ない(ドライブの共有でその人に見る権限が無い)ときは、選べない。アプリからは「まだ使えない」と「見る権限がない」を見分けられないので、案内の文に「ファイル選択画面に出てこない場合は、そのファイルを見る権限がありません。ドライブの共有を確かめてください。」を添える
- 選ばずに閉じた: 何もしない(案内とボタンは出したまま)。自動取得なら手入力で続けられ、コピーならキャンセルできる
- 使えないことは失敗として扱わない。要再連携(6.0.5)にもしない
- 表の最新版の資料名と更新日時の取り直し(6.1)は、その人が使えるファイルだけで行い、使えないファイルはそのままにする(案内も出さない)

### 6.1 案件(U2)

#### 構成要素

案件ヘッダー:

- 「← ホーム」: ホームへ戻る
- 案件名と自分の役割(オーナー / 編集者 / 閲覧者)のバッジ
- 「メンバー n人」: メンバー管理(U3)へ。全役割に表示。モバイルでは出さない
- 「+ 資料を追加」: 資料を追加ダイアログ(6.2)を開く。編集者以上・デスクトップとタブレットだけに表示
- 「⋯」メニュー: オーナー・デスクトップとタブレットだけに表示。「案件名を変更」「案件を削除」

ツールバー:

- 資料名の絞り込み欄: 入力するたびに表を絞る(入力が止まってから反映)。系列内の削除されていない版のどれかの名前に部分一致すれば、その系列の行を出す。大文字・小文字、全角・半角の英数字は区別しない
- 種別フィルタ: すべて / ドキュメント / スライド / スプレッドシート / PDF / その他。最新版の種別で判定する
- 件数: 絞り込み後の行数(系列数)

表:

- 1行は1系列の最新版
- 列: 資料名(先頭に種別アイコン、名前の後ろにタグと、旧版があれば「旧版 n件」)、種別、更新、登録した人(最新版を登録した人)
- タグ: 系列のタグをバッジで出す(どのタグが入り、どの版の番号を添えるか、並び順は System Design Doc 6章「導出する値」の「表の行のタグ」)。そのタグが付いた最も新しい版が最新版なら「提出」、旧版なら「提出 v2」のように版番号を添える。先頭から2つまで出し、残りは「+n」にまとめる。「+n」にマウスを載せると残りのタグを一覧で出す
- 幅が足りないとき: 資料名を省略記号で切り、タグと「旧版 n件」は残す。横パネルが開いている間は、表を資料名と更新の2列にし、タグは1つと「+n」にする。モバイルでは表にタグを出さず、シートの概要と版の欄で出す
- 更新: 最新版の更新日時(System Design Doc 6章「導出する値」の「版の更新日時」)
- 並び順: 既定は更新の新しい順。「資料名」「更新」の列見出しを押すと、その列で並べ替え、もう一度押すと逆順
- 行を押す: その系列を選び、横パネルを開いて最新版を表示する。選んだ行は青の背景で示す
- 行にマウスを載せる: 行の右端に「開く ↗」アイコンを出す。押すと最新版のリンクを別タブで開く(横パネルは開かない)
- 「旧版 n件」を押す: その系列を選び、横パネルを開いて版の欄までスクロールする
- 停止された利用者が登録した資料も、登録した人の名前をそのまま表示する

横パネル(選んだ系列の、選んだ版を表示する):

- 見出し: 種別アイコン、選んだ版の資料名、閉じる「×」
- 「開く ↗」: 選んだ版のリンクを別タブで開く
- 概要: 種別、版番号(最新版には「最新」)、タグ(あれば)、更新日時(日時の書式)、登録した人、変更メモ(あれば)
- 版: 系列の削除されていない版を新しい順に並べる。各行は版番号・資料名・タグ・更新日時・登録した人で、変更メモがあれば2行目に小さく出す。押すとパネルの表示がその版に切り替わる(表の行は系列のまま)
- 参考資料: 選んだ版の参考資料を並べる。表示のしかたは下の「関連資料の表示規則」に従う。規則3・4の行で、相手が最新版でなければ「v2」などを添える
- この資料を参考にした資料: この系列を参考資料にしている資料を、相手の系列ごとに1行にまとめて並べる(どの系列が入るかは System Design Doc 6章「導出する値」)。行には相手の系列の最新版の名前を出す。この系列の削除されていない版が2つ以上あるときは、「この資料の v2 を参考」のように、この系列のどの版を参考にしたかを添える(System Design Doc 6章「導出する値」)。表示のしかたは「関連資料の表示規則」に従う
- 並び順(参考資料・この資料を参考にした資料とも): 同じ案件の資料、他の案件の資料、見る権限のない資料、削除された資料の順。同じ区分の中は名前順
- 操作(編集者以上・デスクトップとタブレットだけに表示):
  - 「新しい版を作る」: 系列の最新版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く。基本の道なので、主操作の見た目(青)で先頭に置く
  - 「これを元に作る」: 選んだ版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く
  - 「新しい版を登録」: 新しい版を登録ダイアログ(6.5.5)を開く。系列の最新版の次の版になる。ドライブ以外の資料や、アプリの外で作った版のための補助の道
  - 「登録内容を編集」: 登録内容を編集ダイアログ(6.5.6)を開く。タグ・変更メモもここで直す
  - 「この版を削除」: 確認ダイアログ「『{資料名}』(v{n})を削除します。アプリの記録から消えます。元の場所にあるファイルは消えません。」の後、選んだ版を削除済みにする

版を削除した後:

| 削除した版 | その後の表示 |
|-----------|-------------|
| 旧版 | 横パネルは系列の最新版を表示する。表の「旧版 n件」を1減らす |
| 最新版(旧版が残っている) | 1つ前の版が最新版になる。表の行と横パネルはその版を表示する |
| 系列の最後の1版 | 表から行を消し、横パネルを閉じる。「資料を削除しました」と通知する |

- 版番号は再利用しない。最新版の v3 を削除した後に新しい版を登録・作成すると、v4 になる(v3 は欠番)

関連資料の表示規則(参考資料・この資料を参考にした資料で共通)。上から順に判定し、最初に当てはまった表示にする:

| 順 | 相手の資料の状態 | 表示 | 押したとき |
|----|-----------------|------|-----------|
| 1 | 相手の案件に自分が参加していない(削除済みかどうかによらない) | 鍵アイコン + 「見る権限のない資料」。名前・案件名・版番号・添え書きは出さない | 押せない |
| 2 | 相手の版が削除済み、または相手の案件が削除済み | 「削除された資料」。名前・案件名・版番号・添え書きは出さない | 押せない |
| 3 | 同じ案件の資料 | 種別アイコン + 資料名 | 横パネルがその資料に切り替わり、表のその行を選ぶ |
| 4 | 自分が参加している他の案件の資料 | 種別アイコン + 資料名 + 「(案件名)」 | その案件の案件画面へ移動し、その資料を選んだ状態で開く |

- 「参加している」の判定と、各規則への当てはめ方は System Design Doc 6章「導出する値」の「関連資料の表示区分」(案件が削除されても元メンバーには規則2が当たる)
- 押したときに開く版: 参考資料の行は参考資料として記録された版、この資料を参考にした資料の行は相手の系列の最新版
- 削除済みの案件の系列は「この資料を参考にした資料」に出ないので、規則2に当たる行は参考資料の向きでだけ出る

| 操作 | 応答 |

| 絞り込み・種別フィルタ | 表をその場で絞る。選んだ系列が条件から外れても、横パネルは開いたまま |
| 行を選ぶ | 横パネルを開く(開いていれば中身を差し替える)。URL にも選んだ系列と版を反映し、再読み込みや共有しても同じ状態で開く |
| 「×」・Esc キー | 横パネルを閉じ、表を全幅に戻す |
| 案件名を変更(オーナー) | 案件名を変更ダイアログ。入力規則は 6.0.3。保存すると見出しとホームの一覧に反映 |

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 読み込み中 | 案件ヘッダーとツールバーは先に出し、表は灰色の仮の行を8行出す |
| 資料が0件(編集者以上・デスクトップとタブレット) | 表の場所に「まだ資料がありません」と「+ 資料を追加」ボタン、「ここから資料を作るか、既にある資料のリンクを登録できます」の補足 |
| 資料が0件(閲覧者、またはモバイル) | 「まだ資料がありません。編集者が資料を追加すると、ここに並びます。」(ボタンは出さない) |
| 絞り込みで0件 | 「条件に合う資料がありません」と「絞り込みを解除」ボタン |
| 表の読み込み失敗 | 表の場所に「資料を読み込めませんでした」と「再読み込み」ボタン |

| 横パネルの読み込み中 | 見出しと「開く」は表の行の情報で先に出し、版・参考資料・参考にした資料の欄は灰色の仮の行を2行ずつ出す |
| 横パネルの読み込み失敗 | 版・参考資料・参考にした資料の欄の代わりに「読み込めませんでした」と「再読み込み」 |
| 横パネルの版・参考資料・参考にした資料が0件 | その欄に「なし」と表示する(欄は消さない) |
| URL で指定された系列・版が無い・削除済み | 横パネルは開かず、表だけを出す。「この資料は削除されたか、見つかりません」と通知する |
| 削除の処理中 | 確認ダイアログの「削除」ボタンを読み込み中にする |
| メタデータの取り直しの失敗 | 何も表示しない。保存済みの名前と更新日時をそのまま出す(認可エラーなら要再連携に切り替える) |

#### メタデータの取り直し

- 対象: 案件画面を開いたとき(開いた人が連携中のとき)、表に並ぶ最新版のうち Google の資料(1.4)で、開いた人のアプリが使えるもの(6.0.9)
- 取るもの: 元の場所での資料名と更新日時
- 反映: 資料名と更新日時を元の場所の値で上書きし、Google から取得した記録を残す(以降、資料名と更新日時は読み取り専用。6.5.6)。値が変わっていれば表と横パネルに反映する。更新日時が変わったときは案件の最終更新も進める(System Design Doc 6章)
- 使えない・見られない資料: 取り直さず、保存済みの値のまま
- 要再連携の人が開いたとき: 取り直さない

```

│ [https://docs.google.com/presentation/d/…    ] │
```

ダイアログを開くと「新しく作る」タブを選んだ状態にする(基本の道)。

#### タブ「リンクで登録」(ドライブ以外の場所にある資料や、既にある資料を登録する補助の道)

| 項目 | 必須 | 仕様 |
|------|------|------|
| リンク | 必須 | http または https で始まる URL。貼り付けた時点で種別を判定する(docs.google.com/document → ドキュメント、/presentation → スライド、/spreadsheets → スプレッドシート、.pdf で終わる → PDF、それ以外 → その他)。drive.google.com/file のリンク(ドライブに置いたファイル)も Google の資料として扱い、資料名と更新日時を取れたら、種別は元の場所の種類で決める(PDF なら PDF、それ以外はその他)。重複は 6.0.4。欄の横に「ドライブから選ぶ」ボタンを置き、押すと Google のファイル選択画面を開く(ドキュメント・スライド・スプレッドシート・PDF を選べる)。選ぶとリンク・資料名・種別・更新日時が入り、そのファイルはアプリで使えるようになる(6.0.9) |
| 資料名 | 必須 | 1〜200文字。Google の資料なら(要再連携でなければ)、リンクを貼った時点で元の場所の名前を取って入れ、欄を読み取り専用にして「ドライブの名前を使います」と添える。アプリがまだ使えないファイルなら 6.0.9 の案内を出す。取れなければ手入力 |
| 種別 | 必須 | リンクから判定した値を初期値にする。変更できる |
| 更新日時 | 任意 | 元の場所での更新日時。Google の資料なら(要再連携でなければ)自動で入れ、欄は読み取り専用。それ以外(自動取得に失敗した場合を含む)は日付ピッカーで日付だけを入れる。未来の日付は選べない。ブラウザのタイムゾーンの0時として保存する。空なら登録日時を使う |
| 参考資料 | 任意 | 名前を入れると、参加している全案件の資料(系列の最新版。削除されていないもの)を候補に出す。候補には種別アイコン・資料名・案件名を出す。20件まで選べる。選んだものはチップで並べ、×で外せる |

- 追加: 新しい系列を作り、その1版目として登録する。ダイアログを閉じ、表に新しい行を出して選び、横パネルを開く。「資料を追加しました」と通知する

#### タブ「新しく作る」(既定のタブ)

| 項目 | 必須 | 仕様 |
|------|------|------|
| 種別 | 必須 | ドキュメント / スライド |
| 資料名 | 必須 | 1〜200文字。この名前でドライブにファイルを作る |
| 参考資料 | 任意 | リンクで登録と同じ |

- 作成: 作成した人のマイドライブ直下に空の資料を作り(6.0.8)、この案件の新しい系列の1版目として登録する
- 作成後: ダイアログを閉じ、表に新しい行を出して選び、横パネルを開く。編集画面を別タブで開く。ブラウザが別タブを止めた場合に備えて、通知「資料を作成しました」に「編集画面を開く ↗」のリンクを必ず添える
- 補足文: 「作成したファイルはマイドライブ直下に置かれます。置き場所と共有設定は、ドライブで変えてください。」

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 資料名・更新日時の自動取得中 | 資料名欄に読み込み中の表示。「追加」は取得が終わるまで押せない |
| アプリがまだ使えないファイル(6.0.9) | 資料名と更新日時を手入力にし、資料名欄の下に 6.0.9 の案内と「このファイルをアプリで使えるようにする」を出す。使えるようになったら自動取得をやり直す。案内を無視して手入力のまま追加してもよい |
| 自動取得できなかった(ドライブの一時的な失敗など) | 資料名欄の下に「資料名を取得できませんでした。入力してください。」。資料名と更新日時を手入力にする |

| ドライブへの作成に失敗・ドライブには作成できたが登録に失敗(新しく作る) | 6.0.8。「このリンクで登録」は、このダイアログの「リンクで登録」タブにそのリンクを入れて開き直す |

| コピー元 | 横パネルで選んでいる版 | 系列の最新版 |

### 6.4 ホーム(U1)

以下の画面例は 8章のデモデータで山田がログインした場合の表示。

#### レイアウト構造

```
┌───────────────────────────────────────────────────────────────────┐
│ weaponx                                                     (ユーザー) │
├───────────────────────────────────────────────────────────────────┤
│ 案件                                                               │
│ [🔍 参加中の案件の資料を検索                        ] [+ 案件を作る]  │
├───────────────────────────────────────────────────────────────────┤
│ 案件名                     自分の役割    資料数    最終更新 ▼         │
│ A社 DX提案                 オーナー        5      2026/09/28          │
│ B社 市場調査               編集者          2      2026/09/14          │
│ 社内テンプレート集          閲覧者          1      2026/08/30          │
└───────────────────────────────────────────────────────────────────┘
```

検索中(案件一覧の場所に結果を出す):

```
│ [🔍 提案書                                     ×] [+ 案件を作る]     │
├───────────────────────────────────────────────────────────────────┤
│ 「提案書」の検索結果 4件                                               │
│ 資料名                     案件             種別        更新           │
│ ▣ 提案書 v3                A社 DX提案       スライド     2026/09/28    │
│ ▣ 提案書 v2     [旧版]      A社 DX提案       スライド     2026/09/21    │
│ ▤ 提案書(B社向け)          B社 市場調査     ドキュメント 2026/09/12    │
│ ▣ 提案書 初稿   [旧版]      A社 DX提案       スライド     2026/09/10    │
```

#### 仕様

案件一覧:

- 参加している、削除されていない案件を並べる。列は案件名・自分の役割・資料数・最終更新(System Design Doc 6章「導出する値」)
- 並び順は最終更新の新しい順。行を押すと案件画面へ
- 「+ 案件を作る」(デスクトップとタブレットだけ): 案件を作るダイアログ。案件名は 6.0.3。作成すると自分がオーナーの案件ができ、その案件画面へ移る。作成中・入力の不備・失敗は 6.0 に従う

横断検索:

- 検索欄に1文字以上入れると、入力が止まってから検索し、案件一覧の場所に結果を出す。「×」か検索欄を空にすると案件一覧に戻る
- 対象: 参加している、削除されていない案件の、削除されていない版の資料名。部分一致。大文字・小文字、全角・半角の英数字は区別しない
- 結果の1行は一致した版。旧版に一致した場合は「旧版」を添える。列は資料名・案件名・種別・更新(その版の更新日時)。並び順は更新の新しい順
- 行を押す: その案件の案件画面へ移り、その系列を選んで横パネルを開き、一致した版を表示する
- 行にマウスを載せると「開く ↗」アイコンを出す(その版のリンクを別タブで開く)
- 最大50件まで出す。それを超えるときは末尾に「50件以上あります。語を足して絞り込んでください。」

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 読み込み中 | 表に灰色の仮の行を5行 |
| 参加している案件が0件(デスクトップとタブレット) | 「まだ参加している案件がありません」「+ 案件を作る」ボタン、「招待されると、ここに案件が表示されます」の補足 |
| 参加している案件が0件(モバイル) | 「まだ参加している案件がありません」と「招待されると、ここに案件が表示されます」(ボタンは出さない) |
| 検索中 | 結果の表に灰色の仮の行を3行 |
| 検索結果が0件 | 「『{語}』に一致する資料はありません」 |
| 読み込み・検索の失敗 | 「読み込めませんでした」と「再読み込み」ボタン |
| 要再連携 | ヘッダーの下に要再連携の帯(3.5) |

### 6.5 その他の画面とダイアログ

#### 6.5.1 ログイン

```
┌──────────────────────────────┐
│           weaponx             │
│  資料のつながりと最新版が分かる   │
│   [ G  Google でログイン ]      │
│ ドライブで資料を作る・資料名を │
│ 読むための許可もあわせて求めます │
│   日本語 | English              │
└──────────────────────────────┘
```

| 状態 | 表示 |
|------|------|
| 通常 | アプリ名、一言説明、「Google でログイン」、表示言語の切り替え |
| 「Google でログイン」を押した後 | Google の画面へ移るまでボタンを読み込み中にする(Google から戻った後の確認はサーバーが行い、終わってから画面を出す) |
| 許可されていないアカウント | 「このアカウント({メール})は利用を許可されていません。管理者に連絡してください。」 |
| 停止されたアカウント | 「このアカウントは停止されています。管理者に連絡してください。」 |
| ドライブの許可が足りない(一部または全部を外した) | 「ドライブの許可が必要です。もう一度ログインし、すべての項目を許可してください。」。ログインさせない |
| 取り消した・Google 側で拒否された | 「ログインできませんでした。許可を取り消した場合はもう一度お試しください。会社の設定で外部アプリとの連携が制限されている場合は利用できません。」。ログインさせない |
| 通信・その他の失敗(戻った後の保存の失敗など) | 「ログインできませんでした。もう一度お試しください。」。ログインさせない |
| ログイン済みで開いた | ホームへ移る |

- ログインでは、Google アカウントの認証とドライブの許可を一緒に求める。両方そろったときだけログインさせ、ドライブ連携を連携中にする(2回目以降は認可情報を新しくする)
- 判定の順: 許可されていないアカウント → 停止されたアカウント → ドライブの許可が足りない。最初に当てはまったものだけを出す
- 利用者の照合: 初回ログインでは、管理者が登録したメールと Google アカウントのメールを照合し、Google アカウントの ID を保存する。2回目以降は Google アカウントの ID で照合する
- 初回ログイン時に Google アカウントの表示名とアイコン画像を保存する。以降のログインで更新する
- ログイン後の行き先: 6.0.7 で元の URL があればそこ、無ければホーム

#### 6.5.2 メンバー管理(U3)

山田(A社 DX提案の唯一のオーナー)が開いた場合の表示:

```
│ ← A社 DX提案   メンバー                              [+ メンバーを招待] │
│ 名前               メール               役割           追加日            │
│ 山田 太郎(自分)    yamada@example.com   [オーナー ▾]※  2026/09/01  [外す]※│
│ 佐藤 花子           sato@example.com     [編集者 ▾]     2026/09/03  [外す] │
│ 鈴木 一郎(停止中)   suzuki@example.com   [閲覧者 ▾]     2026/09/05  [外す] │
│ ※ 無効: オーナーが1人以上必要です                                        │
```

- 「← {案件名}」: 案件画面へ戻る
- オーナー: 役割をプルダウンで変更でき(オーナー / 編集者 / 閲覧者)、選んだ時点で保存する。「外す」でメンバーから外せる(確認ダイアログあり)。自分を外すこともできる
- 自分の役割をオーナーより下げる: 確認ダイアログ「自分の役割を{役割}に変えると、メンバーの管理ができなくなります。」の後に保存し、表を読み取り専用の表示に切り替える
- 最後のオーナー: その行の役割変更と「外す」は無効化し、「オーナーが1人以上必要です」と添える
- オーナー以外: 同じ表を読み取り専用で表示する。「メンバーを招待」「外す」は出さず、役割はプルダウンでなく文字で出す
- 名前の表示: 停止中の利用者は名前の後ろに「(停止中)」を添える。まだログインしていない利用者は名前の欄に「(未ログイン)」と出す
- 並び順: オーナー、編集者、閲覧者の順。同じ役割の中は名前順
- メンバーを招待ダイアログ: 名前かメールで、有効な利用者のうち、まだメンバーでない人を検索して選ぶ。役割を選ぶ(オーナー / 編集者 / 閲覧者、初期値は編集者)。「招待」でメンバーに加わり、その人が次にホームを開いたときから案件が現れる(2.1「次の操作から反映」)。通知メールは送らない
- 招待の候補が0件: 「該当する利用者がいません。利用者の追加は管理者に依頼してください。」
- 自分を外したとき: ホームへ戻る
- 読み込み中: 表に灰色の仮の行を4行。読み込み失敗: 「読み込めませんでした」と「再読み込み」
- 案件に参加していない・案件が無い: 案件画面と同じ「見つからない」表示
- 操作中・成功・失敗: 6.0 に従う

#### 6.5.3 (欠番)

以前の版の「連携設定」画面は廃止した。連携はログインのときに行い、再連携は 6.0.5 に従う。節番号は他の節からの参照を保つため欠番にする。

#### 6.5.4 利用者管理(A1)

```
│ 利用者管理                                               [+ 利用者を追加] │
│ [名前・メールで絞り込み ]                                                │
│ 名前            メール               ロール     状態     最終ログイン        │
│ 山田 太郎(自分) yamada@example.com   管理者     有効     2026/09/30 09:00 [⋯]※│
│ 佐藤 花子       sato@example.com     一般       有効     2026/09/29 18:20 [⋯] │
│ 田中 美咲       tanaka@example.com   一般       有効     2026/09/27 11:02 [⋯] │
│ (未ログイン)    new@example.com      一般       有効     ─                [⋯] │
│ 鈴木 一郎       suzuki@example.com   一般       停止     2026/09/05 16:45 [⋯] │
│ ※ 無効: 自分自身は変更できません                                          │
```

- 「⋯」メニュー: 停止 / 再開(状態に応じてどちらか)、管理者にする / 管理者から外す
- 自分の行の「⋯」は無効化し、「自分自身は変更できません」と添える
- 並び順: 有効な利用者を先に、その中は名前順(未ログインはメール順で末尾)
- 利用者を追加ダイアログ: メールアドレス(1件)と「管理者にする」のチェック。追加した人は「有効」で、まだログインしていなければ名前の欄に「(未ログイン)」
- 停止の確認ダイアログ: 「{メール}を停止します。この人はログインできなくなります。」。この人が唯一のオーナーになっている案件があれば、「この人が唯一のオーナーになっている案件が {n} 件あります。停止すると、その案件ではメンバーの招待・役割の変更・外す、案件名の変更、案件の削除ができなくなります。」を警告色で添える。案件名は出さない
- 停止した人がログイン中なら、次の操作でログイン画面に戻り、停止の表示を出す(6.0.2)
- 入力の不備: 登録済みのメールは「このメールアドレスはすでに登録されています」、形式が違えば「メールアドレスの形式が正しくありません」
- 読み込み中: 表に灰色の仮の行を5行。絞り込みで0件: 「条件に合う利用者がいません」。読み込み失敗: 「読み込めませんでした」と「再読み込み」
- 管理者でない人が開いた: 「この画面を開く権限がありません」と「ホームへ」
- 操作中・成功・失敗: 6.0 に従う

#### 6.5.5 新しい版を登録ダイアログ

- 項目: リンク(必須)、資料名(必須、初期値は最新版の名前)、種別(必須、リンクから判定)、更新日時(任意)、変更メモ(任意、100文字まで、空で始める)、参考資料(初期値は最新版の参考資料を引き継ぐ。外したり足したりできる)
- タグは引き継がない(登録した後に、登録内容を編集で付ける)
- 参考資料の候補からは、同じ系列の版を除く
- 自動取得・入力の規則・状態の表示は資料を追加ダイアログ(6.2)の「リンクで登録」と同じ。リンクの重複は 6.0.4
- 登録すると系列の次の版になり、表の行と横パネルが新しい版を表示する

#### 6.5.6 登録内容を編集ダイアログ

- 横パネルで選んでいる版の、リンク・種別・資料名・更新日時・変更メモ・タグ・参考資料を直す
- タグ: 入力すると、この案件の削除されていない版に付いているタグを候補に出す。Enter か候補を選んで確定し、チップで並べる。×で外す。上限・重複・入力の扱いは 6.0.3
- 変更メモ: 任意。100文字まで
- Google から資料名を取得済みの版(6.1「メタデータの取り直し」の「Google から取得した記録」がある版)は、資料名と更新日時を読み取り専用にし、「ドライブの名前を使います。名前はドライブで変更してください。」と添える
- リンクを変えたら種別を判定し直し、資料名と更新日時を編集できる状態に戻す(保存すると Google から取得した記録を消す)。Google の資料で(要再連携でなければ)取り直せたら、その値を入れて読み取り専用に戻す(保存すると記録を残す)。取り直せなければ手入力にし、6.2 の「アプリがまだ使えないファイル」「自動取得できなかった」または要再連携の表示を出す。リンク欄の「ドライブから選ぶ」も 6.2 と同じ。リンクの重複は 6.0.4
- 参考資料の候補からは、同じ系列の版を除く
- 入力の規則・状態の表示は資料を追加ダイアログ(6.2)と同じ

#### 6.5.7 エラー

| 状態 | 表示 |
|------|------|
| 存在しない URL | 「ページが見つかりません」と戻り先のボタン |
| 想定外の障害(画面全体を表示できない) | 「問題が発生しました。時間をおいてもう一度お試しください。」と戻り先のボタン |

- 戻り先: ログイン中なら「ホームへ」、未ログインなら「ログインへ」

## 9. 今後の検討事項

### 拡張候補

- 地図表示: 記録した参考資料と版の関連を地図で俯瞰する。資料が増えて一覧で追えなくなったら足す(`docs/concept.md` の「俯瞰できる」体験)
- 読む順・未読の管理: 案件に後から入った人向けに、読むべき資料と順番を示す
- ドライブの共有設定の同期: 案件内の役割に合わせてドライブの共有を揃える。3つの役割とドライブの権限の対応を詰めてから判断する
- スプレッドシートの「これを元に作る」「新しい版を作る」: MVP はドキュメントとスライドだけ。コピーの仕組みは同じなので、要望があれば足す
- ドライブ以外の保存先との連携(Box・OneDrive 等)
- 案件から自分で抜ける操作(オーナー以外)
- 停止された唯一のオーナーの案件の救済(管理者によるオーナーの付け替え等)。MVP は停止時の警告だけ
- 削除済みの案件・資料の復元
- 本文検索: 本文を保存しない方針(`docs/01_prd.md` 6章)を見直すときの候補。本文をどこまで預かるかから決め直す
- 操作の記録(誰がいつ登録・削除したかの履歴画面)。このための記録(誰がいつ操作したか)はデータモデルに持っている(System Design Doc 6章)
- 招待の通知(メール等)
- 同時編集の検出(後から保存した人に「他の人が変更しました」と知らせる)。MVP は後勝ち
- 一覧のページ分け(想定規模を超えたとき)
- 版どうしの比較(git の diff にあたる): Google ドキュメントには文書の比較機能があるが、スライドには無い。アプリで差分を出すには本文を読む必要があり、「本文を保存しない」方針と相談になる
- タグでの絞り込み・横断検索(例: 「提出」が付いた版だけを出す)
- Google 以外のログイン(メールのリンク、Microsoft アカウント等)と、ドライブ連携なしでの利用。Google アカウントを持たない人にも使ってもらう必要が出たら判断する

### 既知の制約

- ドライブ以外の場所の資料(リンクで登録した資料)は、リンク先が更新・移動されてもアプリには伝わらない。その資料の最新版の正しさは人の登録に頼る
- 会社の Google Workspace で外部アプリとの連携が制限されている場合、ログインできないので利用できない(ドライブの許可をログインの条件にしたため)
- 案件内の役割は資料そのものの閲覧権限を与えない。メンバーが資料を開けるかは元の場所の共有設定しだい
- Google の資料名はアプリ上で変えられない。名前を変えたいときはドライブで変える
