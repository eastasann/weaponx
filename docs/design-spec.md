# weaponx — 設計仕様書

> **資料の管理をアプリが引き受け、案件・元ネタ・版を作った時点で記録する。資料が増えても「どれが最新で、何を元にしたか」が一覧で分かる。**

---

## 1. プロダクト概要

### 1.1 コンセプト

案件ごとにスライドとドキュメントが増え続ける職種(コンサル・営業・リサーチ職など)に向けた資料管理ツール。資料が増えると、資料どうしの関連・最新版・読むべきものが分からなくなる。この課題を、散らかった後に推測して見える化するのではなく、資料を作った(登録した)時点で「どの案件か」「何を元にしたか」「どれの新しい版か」を事実として記録することで解く。

- 対象: 案件ごとに資料が増え続ける人。まず作者自身が日常で使い、同じ職場の人にも広げる
- 管理の単位: 案件。資料は1つの案件に属し、案件の中では1行に1系列(同じ資料の版の並び)の最新版が並ぶ
- 関連の種類: 元ネタ(この資料を作るときに元にした資料)と版(同じ資料の新しい版)の2種類。どちらも推測せず、人の記録か、アプリの「元にして作る」「新しい版を作る」操作で決まる
- 版の意味: 版は別ファイルとして作られた資料を指す。同じファイルを上書き編集しても版は増えず、更新日時が変わるだけ
- 書く・作る道具: 持たない。Google ドキュメント・スライドなど既存の道具を借り、アプリは管理に徹する

経緯: Phase 0 の `docs/concept.md` は「ドライブの資料を後から読んで関連を地図に描く」だった。Phase 1 の壁打ちで上記に見直した(`docs/brainstorm-notes.md` の「コンセプトからの見直し」)。

### 1.2 プロダクト方針

| 項目 | 方針 |
|------|------|
| 用途 | 自分用の MVP。課金なし。同じ職場の人も招待して使える |
| 対応言語 | 日本語と英語。画面の文言はすべて2言語で用意する。初期値はブラウザの言語設定(日本語以外は英語)で、ユーザーメニューで切り替えられ、選んだ言語はユーザーごとに保存する。利用者が入力した内容(案件名・資料名など)は翻訳しない。日時は言語に合わせた書式で表示する |
| 端末 | デスクトップ優先。スマホでは「案件と資料を探して開く」ことだけができる(6.6 参照) |
| ドライブ連携 | 任意。つながなくても中核(案件・リンク登録・元ネタと版の記録・一覧・検索・招待)は使える。つないだ人は、資料名と更新日時を自動で取れ、アプリから Google ドキュメント・スライドを作れる |
| 資料の実体 | 元の場所(ドライブ・Box・社内サーバ等)に置いたまま。アプリはリンクと管理情報だけを持つ |
| 元の場所への作用 | アプリは元の場所のファイルを消さない・書き換えない。例外は、連携ありの人の操作で新しいファイルを作る(空の資料の作成と、既存資料のコピー)ことだけ |
| 本文 | 保存しない。関連を推測しないので本文を読む必要がない。検索は資料名だけを対象にする |
| 権限の効き方 | 案件内の役割はアプリ上の管理情報に効く。資料そのものを開けるかは、元の場所の権限に従う。ドライブの共有設定は同期しない |

### 1.3 UI設計原則

| 原則 | 内容 |
|------|------|
| 最新版が主役 | 一覧には常に最新版だけを並べる。旧版は求められたときだけ横パネルで見せる。「読むべきなのはこの行」を崩さない |
| 記録は操作のついで | 「元にして作る」「新しい版を作る」では元ネタと版が自動で記録される。人が手で関連を選ぶのは、資料を追加するときの元ネタ欄1か所だけにする |
| 開くまで最短 | 一覧の行にマウスを載せると「開く」アイコンが出て、横パネルを開かずに元の場所へ行ける |
| 許されない操作は出さない | 役割で許されない操作のボタンは表示しない(無効化ではなく非表示)。条件付きでできない操作(最後のオーナーを外すなど)は無効化し、理由を添える |
| 元の場所が正 | 資料の中身と共有は元の場所が決める。アプリは開けない資料を開けるようには見せない。権限のない他案件の資料は「見る権限のない資料」とだけ表示する |
| 高密度で見渡す | 行を詰め、1画面に多くの資料を並べる。装飾より資料名と関連を目立たせる |

## 2. ユーザーロールとフロー

### 2.1 ロール定義

全体のロール(アプリ全体で1人に1つ):

| ロール | 概要 | 主な操作 |
|--------|------|----------|
| 一般ユーザー | 管理者に許可された Google アカウントで入り、案件と資料を管理する人 | 案件の作成、参加している案件での役割に応じた操作、横断検索、自分のドライブ連携のつなぐ・外す、表示言語の切り替え |
| 管理者 | 使える人を管理する人 | 一般ユーザーの操作 + 利用者の追加・停止・再開、管理者の付与・解除 |

案件内の役割(案件ごとに1人に1つ):

| 役割 | 概要 | 主な操作 |
|------|------|----------|
| オーナー | 案件の責任者。複数置ける | 編集者の操作 + メンバーの招待・役割の変更・外す、案件名の変更、案件の削除 |
| 編集者 | 案件の資料を管理する人 | 閲覧者の操作 + 資料の追加、新しい版の登録、元にして作る・新しい版を作る(連携ありのみ)、登録内容の編集、版の削除 |
| 閲覧者 | 案件の資料を見るだけの人 | 資料一覧・関連・版の閲覧、資料を開く、メンバー一覧の閲覧 |

権限の規則:

- 管理者でも、参加していない案件の案件名・資料・メンバーは見られない。例外は、停止の確認画面に出す「唯一のオーナーになっている案件の件数」だけ
- 案件の作成者は、その案件の最初のオーナーになる
- 最後のオーナーは、自分を外すことも自分の役割を変えることもできない
- 停止された利用者はログインできない。案件での役割・登録した資料・登録者としての名前表示は残る
- 管理者は自分自身を停止することも、自分の管理者を外すこともできない(管理者がいなくなるのを防ぐ)
- 最初の管理者は初期設定で登録する(手順は Phase 3 で決める)

### 2.2 フロー全体像

```
全員(探して開く・コアフロー):
  ログイン → ホーム(案件一覧) → 案件 → 資料を選ぶ → 横パネルで元ネタ・版・派生資料をたどる → 開く(別タブ)

全員(横断で探す):
  ホーム → 検索欄に資料名を入力 → 結果の資料を選ぶ → 案件(その資料を選んだ状態) → 開く(別タブ)

編集者以上(リンクで登録する):
  案件 → 資料を追加 → リンクを貼る → 名前・種別・元ネタを入力 → 一覧に並ぶ

編集者以上(新しい版を登録する):
  案件 → 資料を選ぶ → 新しい版を登録 → リンクを貼る → 系列の最新版になる

編集者以上・連携あり(元にして作る / 新しい版を作る):
  案件 → 資料を選ぶ → これを元に作る / 新しい版を作る → 名前・追加先を確認 → 編集画面が別タブで開く(元ネタ・版は自動で記録)

オーナー:
  案件 → メンバー → 招待・役割の変更・外す

管理者:
  ユーザーメニュー → 利用者管理 → 利用者を追加・停止・再開・管理者の付与
```

## 3. 画面一覧

画面の存在・目的・レイアウト・認証要否はこのドキュメントが所有する。レイアウトパターン(P1〜P4)の定義は 4.1 を参照。

### 3.1 共通画面

| 画面名 | 目的 | 説明 | レイアウト | 認証 |
|--------|------|------|-----------|------|
| ログイン | 利用を始める | Google アカウントでログインする。許可されていない・停止されたアカウントには理由を表示する。ログイン前でも表示言語を切り替えられる | P1 中央集中 | 不要 |

### 3.2 一般ユーザー面(管理者も使う)

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| U1 | ホーム | 案件を選ぶ・作る、資料を横断で探す | 参加している案件の一覧と「案件を作る」。検索欄に入力すると、参加している全案件の資料を資料名で検索し、案件一覧の場所に結果を出す | P3 一覧 | 要 |
| U2 | 案件 | 資料を探して開く(コア画面) | 資料を表形式で並べる。1行は1系列の最新版。資料を選ぶと右に横パネルが開き、版・元ネタ・派生資料と操作を出す | P2 一覧 + 右パネル | 要(案件のメンバーのみ) |
| U3 | メンバー管理 | 案件の参加者を管理する | 案件のメンバー一覧。オーナーは招待・役割の変更・外すができる。他の役割は閲覧だけ | P3 一覧 | 要(案件のメンバーのみ) |
| U4 | 連携設定 | ドライブ連携を管理する | 連携の状態を表示し、つなぐ・外す・つなぎ直すを行う | P4 設定フォーム | 要 |

### 3.3 管理者面

| # | 画面名 | 目的 | 説明 | レイアウト | 認証 |
|---|--------|------|------|-----------|------|
| A1 | 利用者管理 | 使える人を管理する | 利用者の一覧。追加・停止・再開・管理者の付与と解除 | P3 一覧 | 要(管理者のみ) |

### 3.4 ダイアログ一覧

画面ではなく、画面の上に重ねて開くダイアログ(パターン D)。

| ダイアログ | 開く場所 | 目的 | 対象 |
|-----------|---------|------|------|
| 案件を作る | ホーム | 案件名を入れて案件を作る | 全員 |
| 資料を追加 | 案件 | リンクで登録する。連携ありなら新しく作ることもできる | 編集者以上 |
| 新しい版を登録 | 案件(横パネル) | リンクを貼って系列の新しい版として登録する | 編集者以上 |
| 作成(これを元に作る / 新しい版を作る) | 案件(横パネル) | 選んだ資料をコピーして新しい資料・新しい版を作る | 編集者以上・連携あり |
| 登録内容を編集 | 案件(横パネル) | 選んだ版の名前・リンク・種別・更新日時・元ネタを直す | 編集者以上 |
| 案件名を変更 | 案件 | 案件名を直す | オーナー |
| メンバーを招待 | メンバー管理 | 許可済みの利用者を選び、役割を決めて招待する | オーナー |
| 利用者を追加 | 利用者管理 | 利用を許可する Google アカウントを追加する | 管理者 |
| 確認ダイアログ | 各画面 | 削除・停止・連携の解除など、取り消しにくい操作の前に確認する | 操作できる人 |

### 3.5 全画面共通の要素

- ヘッダー: 左にアプリ名 weaponx(押すとホーム)。右にユーザーアイコン。アイコンを押すとユーザーメニューが開く
- ユーザーメニュー: 表示言語(日本語 / English)、連携設定、利用者管理(管理者にだけ表示)、ログアウト
- 連携切れの帯: ドライブ連携が「要再連携」の状態のとき、ヘッダーの下に「ドライブ連携の有効期限が切れました」と「連携設定へ」を表示する

## 4. デザインシステム

### 4.1 レイアウトパターン定義

| パターン | 形 | 使う場面 |
|---------|-----|---------|
| P1 中央集中 | 画面中央に1枚のカード。ヘッダーなし | ログイン前の、1つの操作だけに注目させる画面 |
| P2 一覧 + 右パネル | 上にツールバー、下に全幅の表。行を選ぶと右側にパネルが開き、表の幅が縮む。閉じると全幅に戻る | 一覧を見ながら、選んだ1件の詳細と関連をたどる画面 |
| P3 一覧 | 上にページ見出しとツールバー(検索欄・主操作ボタン)、下に全幅の表 | 同じ種類のものを並べて選ぶ・管理する画面 |
| P4 設定フォーム | 幅を絞った1カラムに、状態表示と操作を縦に並べる | 1つの設定の状態を確認して変える画面 |
| D ダイアログ | 画面中央に重ねるモーダル。背面は暗くし、操作できない | 画面を離れずに短い入力をする場面 |

### 4.2 画面 × レイアウト マッピング

| # | 画面 | パターン | スクロール | 根拠 |
|---|------|----------|-----------|------|
| - | ログイン | P1 | なし | ログインボタン1つに注目させる |
| U1 | ホーム | P3 | 表だけ縦にスクロール(ヘッダー・ツールバーは固定) | 案件を並べて選ぶ。検索結果も同じ表の形で出す |
| U2 | 案件 | P2 | 表と横パネルがそれぞれ独立して縦にスクロール | 一覧を見たまま版・元ネタ・派生資料をたどるのがコアフロー |
| U3 | メンバー管理 | P3 | 表だけ縦にスクロール | メンバーを並べて役割を管理する |
| U4 | 連携設定 | P4 | 通常は収まる | 連携の状態1つを確認して変える |
| A1 | 利用者管理 | P3 | 表だけ縦にスクロール | 利用者を並べて状態を管理する |

### 4.3 レスポンシブ方針

| ブレイクポイント | 幅 | 対応 |
|-----------------|-----|------|
| デスクトップ | ≥1024px | すべての機能を提供する。P2 の横パネルは表の右に並べる |
| タブレット | 768〜1023px | すべての機能を提供する。P2 の横パネルは表の上に重ねて右から出す(表の幅は縮めない) |
| モバイル | <768px | 「探して開く」だけを提供する。ホームと案件は閲覧でき、変更系のボタン(案件を作る・資料を追加・版・編集・削除)は表示しない。案件の表は資料名と更新日時の2列にし、横パネルは全画面のシートで開く。メンバー管理・連携設定・利用者管理は「この画面はパソコンで開いてください」とだけ表示する |

### 4.4 ビジュアルデザイン方針

具体的な値(色コード・フォントサイズ等)は Phase 3 で `docs/06_design-tokens.json` として確定する。ここでは方向性だけを決める。

| 項目 | 方針 |
|------|------|
| トーン&ムード | 落ち着いた業務系。装飾を抑え、資料の名前と関連が主役になる見た目。職場で他の人に見られても浮かない |
| カラーの方向性 | 青系を基調にする。主操作ボタン・リンク・選択中の行に青を使い、背景と文字はグレー系でまとめる。資料の種別は色ではなくアイコンで区別する。警告(連携切れ)と破壊的操作(削除・停止)には、基調の青と区別できる警告色・危険色を1色ずつ使う |
| タイポグラフィの方向性 | 和文・欧文ともゴシック系(サンセリフ)。日付と件数は桁がそろう数字にする。2言語で文字量が変わるので、ボタンや列見出しは英語の長さでも崩れない幅にする |
| ライト/ダークモード | 両対応。OS の設定に従って切り替える(アプリ内の切り替えは持たない)。色はすべてトークンで持ち、ライトとダークの2セットを用意する |
| 情報密度 | 高め。表の行の高さを詰め、1画面に多くの資料を並べる。余白は区切りが分かる最小限にする |

資料の種別とアイコン:

| 種別 | 表示名(日本語 / 英語) | アイコンの方向性 |
|------|---------------------|-----------------|
| google_doc | ドキュメント / Document | 文書 |
| google_slides | スライド / Slides | スライド |
| google_sheets | スプレッドシート / Spreadsheet | 表 |
| pdf | PDF / PDF | PDF ファイル |
| other | その他 / Other | リンク |

案件ヘッダー:

- 「← ホーム」: ホームへ戻る
- 案件名と自分の役割(オーナー / 編集者 / 閲覧者)のバッジ
- 「メンバー n人」: メンバー管理(U3)へ。全役割に表示
- 「+ 資料を追加」: 資料を追加ダイアログ(6.2)を開く。編集者以上・デスクトップとタブレットだけに表示
- 「⋯」メニュー: オーナーにだけ表示。「案件名を変更」「案件を削除」

ツールバー:

- 資料名の絞り込み欄: 入力するたびに表を絞る(入力が止まってから反映)。系列内のどれかの版の名前に部分一致すれば、その系列の行を出す。大文字・小文字、全角・半角の英数字は区別しない
- 種別フィルタ: すべて / ドキュメント / スライド / スプレッドシート / PDF / その他。最新版の種別で判定する
- 件数: 絞り込み後の行数(系列数)

表:

- 1行は1系列の最新版(削除されていない版のうち、版番号が最大のもの)
- 列: 資料名(先頭に種別アイコン、名前の後ろに旧版があれば「旧版 n件」)、種別、更新、登録した人(最新版を登録した人)
- 更新: 最新版の「元の場所での更新日時」。無ければ最新版の登録日時
- 並び順: 既定は更新の新しい順。「資料名」「更新」の列見出しを押すと、その列で並べ替え、もう一度押すと逆順
- 行を押す: その系列を選び、横パネルを開く。選んだ行は青の背景で示す
- 行にマウスを載せる: 行の右端に「開く ↗」アイコンを出す。押すと最新版のリンクを別タブで開く(横パネルは開かない)
- 「旧版 n件」を押す: その系列を選び、横パネルを開いて版の欄までスクロールする
- 停止された利用者が登録した資料も、登録した人の名前をそのまま表示する

横パネル(選んだ系列の、選んだ版を表示する):

- 見出し: 種別アイコン、選んだ版の資料名、閉じる「×」
- 「開く ↗」: 選んだ版のリンクを別タブで開く
- 概要: 種別、版番号(最新版には「最新」)、更新日時、登録した人
- 版: 系列の版を新しい順に並べる。各行は版番号・資料名・更新日時・登録した人。押すとパネルの表示がその版に切り替わる(表の行は系列のまま)。削除された版は表示しない
- 元ネタ: 選んだ版の元ネタを並べる。表示のしかたは下の「関連資料の表示規則」に従う
- この資料を元にした資料: 系列のどれかの版を元ネタにしている資料を並べる。どの版を元にしたかを小さく添える(例: 「v2 を元に作成」)
- 操作(編集者以上・デスクトップとタブレットだけに表示):
  - 「新しい版を作る」: 連携あり、かつ系列の最新版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く
  - 「これを元に作る」: 連携あり、かつ選んだ版がドキュメントかスライドのときに表示。作成ダイアログ(6.3)を開く
  - 連携なしの人には、上の2つの代わりに「ドライブと連携すると、ここから新しい版や資料を作れます(連携設定へ)」という案内を1行出す
  - 「新しい版を登録」: 新しい版を登録ダイアログ(6.5.5)を開く。系列の最新版の次の版になる
  - 「登録内容を編集」: 登録内容を編集ダイアログ(6.5.6)を開く
  - 「この版を削除」: 確認ダイアログの後、選んだ版を削除済みにする。最新版を消すと1つ前の版が最新版になる。すべての版を消すと、その行は一覧から消える

関連資料の表示規則(元ネタ・この資料を元にした資料で共通):

| 相手の資料の状態 | 表示 | 押したとき |
|-----------------|------|-----------|
| 同じ案件の資料 | 種別アイコン + 資料名(版が最新でなければ「v2」などを添える) | 横パネルがその資料(その版)に切り替わり、表のその行を選ぶ |
| 自分が参加している他の案件の資料 | 種別アイコン + 資料名 + 「(案件名)」 | その案件の案件画面へ移動し、その資料(その版)を選んだ状態で開く |
| 自分が参加していない案件の資料 | 鍵アイコン + 「見る権限のない資料」。名前も案件名も出さない | 押せない |
| 削除済みの資料、または削除済みの案件の資料 | 「削除された資料」。名前は出さない | 押せない |

#### ユーザー操作とシステムの応答

| 操作 | 応答 |
|------|------|
| 案件画面を開く | 表を読み込む。連携ありの人が開いた場合は、あわせて表に並ぶ Google の資料(最新版)の名前と更新日時を裏で取り直し、変わっていれば表を更新する(6.1 末尾「メタデータの取り直し」) |
| 絞り込み・種別フィルタ | 表をその場で絞る。選んだ系列が条件から外れても、横パネルは開いたまま |
| 行を選ぶ | 横パネルを開く(開いていれば中身を差し替える)。URL にも選んだ資料を反映し、再読み込みや共有しても同じ状態で開く |
| 「×」・Esc キー | 横パネルを閉じ、表を全幅に戻す |
| 案件名を変更(オーナー) | 案件名を変更ダイアログ。1〜100文字。保存すると見出しとホームの一覧に反映 |
| 案件を削除(オーナー) | 確認ダイアログ「『{案件名}』を削除します。資料の記録は一覧と検索から消えます。元の場所にあるファイルは消えません。」→ 削除するとホームへ戻り、「案件を削除しました」と通知する |
| 削除の失敗・保存の失敗 | 画面上部に通知「保存できませんでした。もう一度お試しください。」。入力中のダイアログは閉じない |

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 読み込み中 | 案件ヘッダーとツールバーは先に出し、表は灰色の仮の行を8行出す |
| 資料が0件(編集者以上) | 表の場所に「まだ資料がありません」と「+ 資料を追加」ボタン、「リンクを貼るだけで登録できます」の補足 |
| 資料が0件(閲覧者) | 「まだ資料がありません。編集者が資料を追加すると、ここに並びます。」 |
| 絞り込みで0件 | 「条件に合う資料がありません」と「絞り込みを解除」ボタン |
| 読み込み失敗 | 表の場所に「資料を読み込めませんでした」と「再読み込み」ボタン |
| 案件が無い・参加していない・削除済み | 画面全体に「この案件は見つからないか、参加していません」と「ホームへ」ボタン。どの理由かは区別しない |
| 横パネルの版・元ネタ・派生資料が0件 | その欄に「なし」と表示する(欄は消さない) |
| URL で指定された資料が無い・削除済み | 横パネルは開かず、表だけを出す。画面上部に「指定された資料は見つかりませんでした」と通知する |
| メタデータの取り直しに失敗 | 何も表示しない。保存済みの名前と更新日時をそのまま出す |

#### メタデータの取り直し

- 対象: 連携ありの人が案件画面を開いたとき、表に並ぶ最新版のうち Google の資料(ドキュメント・スライド・スプレッドシート)
- 取るもの: 元の場所での資料名と更新日時
- 反映: 変わっていれば保存し、表と横パネルに反映する。資料名が変わっていた場合も、アプリ上の資料名を元の場所に合わせる
- 見られない資料: その人のドライブ権限で見られない資料は取り直さず、保存済みの値のまま
- 連携なしの人が開いたとき: 取り直さない

### 6.2 資料を追加ダイアログ

案件画面の「+ 資料を追加」から開く。編集者以上。

#### レイアウト構造

```
┌ 資料を追加 ───────────────────────────────────┐
│ ( リンクで登録 )  ( 新しく作る )   ← 連携ありのときだけタブを出す │
│                                               │
│ リンク *                                       │
│ [https://docs.google.com/presentation/d/…    ] │
│ 資料名 *                                       │
│ [提案書 初稿                                  ] │ ← 連携ありで Google の資料なら自動入力
│ 種別 *              更新日時                    │
│ [スライド ▾]        [2026/09/10 ]              │ ← 連携ありで Google の資料なら自動入力
│ 元ネタ                                         │
│ [名前で検索…                                  ] │
│   ▤ 調査レポート ×   ▣ 提案テンプレート(社内テンプレ集) × │
│                                               │
│                         [キャンセル] [追加]      │
└───────────────────────────────────────────────┘
```

#### タブ「リンクで登録」(全員)

| 項目 | 必須 | 仕様 |
|------|------|------|
| リンク | 必須 | http または https で始まる URL。貼り付けた時点で種別を判定する(docs.google.com/document → ドキュメント、/presentation → スライド、/spreadsheets → スプレッドシート、.pdf で終わる → PDF、それ以外 → その他) |
| 資料名 | 必須 | 1〜200文字。連携ありで Google の資料なら、リンクを貼った時点で元の場所の名前を取って入れる(書き換えてよい)。取れなければ空のまま |
| 種別 | 必須 | リンクから判定した値を初期値にする。変更できる |
| 更新日時 | 任意 | 元の場所での更新日時。連携ありで Google の資料なら自動で入れ、欄は読み取り専用。それ以外は手入力できる。空なら一覧では登録日時を使う |
| 元ネタ | 任意 | 名前を入れると、参加している全案件の資料(系列の最新版)を候補に出す。候補には種別アイコン・資料名・案件名を出す。複数選べる。選んだものはチップで並べ、×で外せる |

- 追加: 新しい系列を作り、その1版目として登録する。ダイアログを閉じ、表に新しい行を出して選び、横パネルを開く
- 同じ案件に同じリンクの資料がすでにある場合: 追加せず、リンク欄の下に「この案件には同じリンクの資料がすでにあります: {資料名}」と、その資料を選ぶリンクを出す。別の案件に同じリンクがあるのは許す

#### タブ「新しく作る」(連携ありのみ)

| 項目 | 必須 | 仕様 |
|------|------|------|
| 種類 | 必須 | ドキュメント / スライド |
| 資料名 | 必須 | 1〜200文字 |
| 元ネタ | 任意 | リンクで登録と同じ |

- 作成: 作成した人のドライブに空の資料を作り、この案件の新しい系列の1版目として登録し、編集画面を別タブで開く。作成したファイルのドライブ上の置き場所は Phase 3 で決める
- 補足文: 「作成したファイルの共有設定は、ドライブで行ってください。」

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 資料名・更新日時の自動取得中 | 資料名欄に読み込み中の表示。入力はできる |
| 自動取得できなかった(見る権限がない等) | 資料名欄の下に「資料名を取得できませんでした。入力してください。」 |
| 必須項目が空・リンクの形式が違う・200文字を超える | 各欄の下に理由を出し、「追加」は押せない |
| 元ネタの候補が0件 | 候補欄に「一致する資料がありません」 |
| 作成中(新しく作る) | 「作成」ボタンを読み込み中にし、ダイアログを閉じない |
| 作成に失敗(新しく作る) | 「ドライブに資料を作れませんでした。もう一度お試しください。」 |
| 連携切れ(新しく作る) | 「ドライブ連携の有効期限が切れました。」と「連携設定へ」 |
| 保存に失敗 | ダイアログ上部に「保存できませんでした。もう一度お試しください。」。入力は保つ |

### 6.3 作成ダイアログ(これを元に作る / 新しい版を作る)

横パネルから開く。編集者以上・連携ありのみ。元の資料をドライブ上でコピーして新しいファイルを作る。

```
┌ これを元に作る ─────────────────────────────┐
│ 元の資料: ▣ 提案書 v3(A社 DX提案)            │
│ 資料名 *                                     │
│ [提案書 v3 のコピー                         ] │
│ 追加先の案件 *                                │
│ [A社 DX提案 ▾]                               │
│ 作成したファイルの共有設定は、ドライブで行ってください。│
│                        [キャンセル] [作成]     │
└─────────────────────────────────────────────┘
```

| | これを元に作る | 新しい版を作る |
|---|---------------|---------------|
| コピー元 | 横パネルで選んでいる版 | 系列の最新版 |
| 資料名の初期値 | 「{元の名前} のコピー」 | 元の名前のまま |
| 追加先 | 自分が編集者以上の案件から選ぶ(初期値は今の案件) | 今の案件(変更不可) |
| 登録のされ方 | 追加先の案件に新しい系列を作り、その1版目にする。元ネタにコピー元の版を記録する | 同じ系列の次の版にする。元ネタは前の版の元ネタを引き継ぐ |
| 作成後 | 編集画面を別タブで開く。追加先が今の案件ならその行を選ぶ。別の案件なら「{案件名} に作成しました」と、その案件へのリンクを通知する | 編集画面を別タブで開く。系列の行はそのままで、横パネルが新しい版を表示する |

| 状態 | 表示 |
|------|------|
| 作成中 | 「作成」ボタンを読み込み中にし、ダイアログを閉じない |
| コピー元を見る権限がない | 「元の資料を開く権限がないため、コピーできません。」 |
| 連携切れ | 「ドライブ連携の有効期限が切れました。」と「連携設定へ」 |
| その他の失敗 | 「ドライブに資料を作れませんでした。もう一度お試しください。」 |

### 6.4 ホーム(U1)

#### レイアウト構造

```
┌───────────────────────────────────────────────────────────────────┐
│ weaponx                                                     (ユーザー) │
├───────────────────────────────────────────────────────────────────┤
│ 案件                                                               │
│ [🔍 参加中の案件の資料を検索                        ] [+ 案件を作る]  │
├───────────────────────────────────────────────────────────────────┤
│ 案件名                     自分の役割    資料数    最終更新 ▼         │
│ A社 DX提案                 オーナー       12      2026/09/28          │
│ B社 市場調査               編集者          8      2026/09/25          │
│ 社内テンプレート集          閲覧者         20      2026/08/30          │
└───────────────────────────────────────────────────────────────────┘
```

検索中(案件一覧の場所に結果を出す):

```
│ [🔍 提案書                                     ×] [+ 案件を作る]     │
├───────────────────────────────────────────────────────────────────┤
│ 「提案書」の検索結果 4件                                               │
│ 資料名                     案件             種別      更新             │
│ ▣ 提案書 v3                A社 DX提案       スライド   2026/09/28      │
│ ▣ 提案書 初稿   [旧版]      A社 DX提案       スライド   2026/09/10      │
│ ▣ 提案テンプレート          社内テンプレート集 スライド   2026/08/30      │
│ ▤ 提案書(B社向け)          B社 市場調査     ドキュメント 2026/09/12     │
```

#### 仕様

案件一覧:

- 参加している案件(削除済みは除く)を並べる。列は案件名・自分の役割・資料数(削除されていない系列の数)・最終更新(案件内の資料の登録・更新、または案件名の変更のうち最も新しい日時)
- 並び順は最終更新の新しい順。行を押すと案件画面へ
- 「+ 案件を作る」(デスクトップとタブレットだけ): 案件を作るダイアログ。案件名1〜100文字。作成すると自分がオーナーの案件ができ、その案件画面へ移る

横断検索:

- 検索欄に1文字以上入れると、入力が止まってから検索し、案件一覧の場所に結果を出す。「×」か検索欄を空にすると案件一覧に戻る
- 対象: 参加している案件の、削除されていない資料のすべての版の資料名。部分一致。大文字・小文字、全角・半角の英数字は区別しない
- 結果の1行は一致した版。旧版に一致した場合は「旧版」を添える。列は資料名・案件名・種別・更新。並び順は更新の新しい順
- 行を押す: その案件の案件画面へ移り、その系列を選んで横パネルを開き、一致した版を表示する
- 行にマウスを載せると「開く ↗」アイコンを出す(その版のリンクを別タブで開く)
- 最大50件まで出す。それを超えるときは末尾に「50件以上あります。語を足して絞り込んでください。」

#### 状態ごとの表示

| 状態 | 表示 |
|------|------|
| 読み込み中 | 表に灰色の仮の行を5行 |
| 参加している案件が0件 | 「まだ参加している案件がありません」「+ 案件を作る」ボタン、「招待されると、ここに案件が表示されます」の補足 |
| 検索中 | 結果の表に灰色の仮の行を3行 |
| 検索結果が0件 | 「『{語}』に一致する資料はありません」 |
| 読み込み・検索の失敗 | 「読み込めませんでした」と「再読み込み」ボタン |
| 連携切れ | ヘッダーの下に連携切れの帯(3.5) |

#### 6.5.2 メンバー管理(U3)

```
│ 名前           メール                  役割          追加日             │
│ 山田 太郎(自分) yamada@example.com     [オーナー ▾]   2026/09/01   [外す] │
│ 佐藤 花子       sato@example.com       [編集者 ▾]     2026/09/03   [外す] │
│ 鈴木 一郎(停止中) suzuki@example.com   [閲覧者 ▾]     2026/09/05   [外す] │
```

- オーナー: 役割をプルダウンで変更でき(オーナー / 編集者 / 閲覧者)、「外す」でメンバーから外せる(確認ダイアログあり)。自分を外すこともできる
- 最後のオーナー: その行の役割変更と「外す」は無効化し、「オーナーが1人以上必要です」と添える
- オーナー以外: 同じ表を読み取り専用で表示する。「メンバーを招待」「外す」は出さない
- 停止中の利用者は名前の後ろに「(停止中)」を添える
- メンバーを招待ダイアログ: 名前かメールで、許可済み(停止されていない)の利用者のうち、まだメンバーでない人を検索して選ぶ。役割を選ぶ(初期値は編集者)。「招待」でメンバーに加わり、その人の次のログイン以降、ホームに案件が現れる。通知メールは送らない
- 招待の候補が0件: 「該当する利用者がいません。利用者の追加は管理者に依頼してください。」
- 自分を外したとき: ホームへ戻る
- 読み込み失敗: 「読み込めませんでした」と「再読み込み」。案件に参加していない: 案件画面と同じ表示

#### 6.5.3 連携設定(U4)

| 連携の状態 | 表示と操作 |
|-----------|-----------|
| 未連携 | 「ドライブと連携すると、資料名と更新日時を自動で取得し、アプリから Google ドキュメント・スライドを作れます。連携しなくても、リンクで登録すればすべての管理機能を使えます。」と「ドライブと連携する」 |
| 連携中 | 「連携中」、連携した日時、「連携を解除」(確認ダイアログあり) |
| 要再連携(許可が取り消された・期限切れ) | 警告色で「連携の有効期限が切れました」と「もう一度連携する」 |
| Google の許可画面で取り消した・失敗した | 「連携できませんでした。会社の設定で外部アプリとの連携が制限されている場合があります。」 |

- 連携はログインしているのと同じ Google アカウントで行う
- 連携を解除しても、登録済みの資料と、アプリで作ったファイルはそのまま残る

#### 6.5.4 利用者管理(A1)

```
│ 利用者管理                                               [+ 利用者を追加] │
│ [名前・メールで絞り込み ]                                                │
│ 名前         メール                 ロール     状態     最終ログイン        │
│ 山田 太郎(自分) yamada@example.com  管理者     有効     2026/09/30          │
│ 佐藤 花子     sato@example.com      一般       有効     2026/09/29  [⋯]    │
│ (未ログイン)  new@example.com       一般       有効     ─           [⋯]    │
│ 鈴木 一郎     suzuki@example.com    一般       停止     2026/09/05  [⋯]    │
```

- 「⋯」メニュー: 停止 / 再開(状態に応じてどちらか)、管理者にする / 管理者から外す
- 自分の行には「⋯」を出さない
- 利用者を追加ダイアログ: メールアドレス(1件)と「管理者にする」のチェック。追加した人は「有効」で、まだログインしていなければ名前の欄に「(未ログイン)」
- 停止の確認ダイアログ: 「{メール}を停止します。この人はログインできなくなります。」。この人が唯一のオーナーになっている案件があれば、「この人が唯一のオーナーになっている案件が {n} 件あります。停止すると、その案件ではメンバーの招待・役割の変更と案件の削除ができなくなります。」を警告色で添える。案件名は出さない
- 停止した人がログイン中なら、次の操作でログイン画面に戻り、停止の表示を出す
- 登録済みのメールを追加した: 「このメールアドレスはすでに登録されています」。形式が違う: 「メールアドレスの形式が正しくありません」
- 0件になることはない(自分がいる)。絞り込みで0件: 「条件に合う利用者がいません」。読み込み失敗: 「読み込めませんでした」と「再読み込み」
- 管理者でない人が開いた: 「この画面を開く権限がありません」と「ホームへ」

#### 6.5.5 新しい版を登録ダイアログ

- 項目: リンク(必須)、資料名(必須、初期値は最新版の名前)、種別(必須、リンクから判定)、更新日時(任意)、元ネタ(初期値は最新版の元ネタを引き継ぐ。外したり足したりできる)
- 自動取得・入力チェック・状態の表示は資料を追加ダイアログ(6.2)と同じ
- 登録すると系列の次の版になり、横パネルが新しい版を表示する。表の行も新しい版の内容になる
- 系列内の他の版と同じリンクは登録できない(「この系列にはすでに同じリンクの版があります」)

#### 6.5.6 登録内容を編集ダイアログ

- 横パネルで選んでいる版の、資料名・リンク・種別・更新日時・元ネタを直す
- 入力チェックは資料を追加ダイアログと同じ。リンクを変えたら種別を判定し直し、連携ありなら資料名と更新日時を取り直す
- 元ネタに、同じ系列の版は選べない(候補に出さない)

### 6.6 モバイルでの動き

- ホーム: 案件一覧(案件名と最終更新の2列)と横断検索。「案件を作る」は出さない
- 案件: 表は資料名と更新の2列。行を押すと横パネルの内容を全画面のシートで開く。シートには「開く」・概要・版・元ネタ・この資料を元にした資料だけを出し、操作の欄は出さない
- メンバー管理・連携設定・利用者管理: 「この画面はパソコンで開いてください」と「ホームへ」だけを出す

## 7. データモデル

論理設計。Phase 3 で ORM のスキーマに変換する。Phase 1 の「関連」エンティティは、版を「系列 + 版番号」、元ネタを「元ネタ表」の2つに分けて持つ形にした。最新版と旧版の件数を一覧で速く出すため。

### ER図

```
users 1──N project_members N──1 projects
users 1──0..1 drive_connections
projects 1──N document_series 1──N documents
documents 1──N document_sources N──1 documents     (元ネタ。他案件の資料も指せる)
users 1──N documents                               (登録した人)
```

### テーブル定義

共通: すべての id は UUID。日時はタイムゾーン付き。created_at / updated_at は全テーブルに持つ(表では省略する場合がある)。

#### users(利用者)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| email | 文字列 | 必須 | Google アカウントのメール。小文字にそろえて保存。一意 |
| display_name | 文字列 | 任意 | 初回ログイン時に Google から取得。未ログインなら空 |
| avatar_url | 文字列 | 任意 | Google のアイコン画像の URL |
| global_role | 列挙 | 必須 | member(一般) / admin(管理者)。既定 member |
| status | 列挙 | 必須 | active(有効) / suspended(停止)。既定 active |
| locale | 列挙 | 任意 | ja / en。空ならブラウザの言語設定に従う |
| last_login_at | 日時 | 任意 | 最終ログイン |
| created_by | UUID | 任意 | 追加した管理者(users.id)。初期設定で登録した最初の管理者は空 |
| created_at / updated_at | 日時 | 必須 | |

#### drive_connections(ドライブ連携)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| user_id | UUID | 必須 | 主キー兼 users.id への参照。1人1連携 |
| status | 列挙 | 必須 | active(連携中) / needs_reauth(要再連携) |
| credentials | 暗号化した値 | 必須 | Google の認可情報。保存と暗号化の方法は Phase 3 で決める |
| connected_at | 日時 | 必須 | 連携した日時 |
| created_at / updated_at | 日時 | 必須 | |

- 連携を解除したら行を消す。行が無いことを「未連携」とする

#### projects(案件)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| name | 文字列 | 必須 | 1〜100文字。一意にはしない |
| created_by | UUID | 必須 | 作成した人(users.id) |
| deleted_at | 日時 | 任意 | 削除した日時。値があれば削除済み |
| deleted_by | UUID | 任意 | 削除した人 |
| created_at / updated_at | 日時 | 必須 | updated_at は案件名の変更で更新する |

#### project_members(案件メンバー)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| project_id | UUID | 必須 | projects.id。主キーの一部 |
| user_id | UUID | 必須 | users.id。主キーの一部 |
| role | 列挙 | 必須 | owner(オーナー) / editor(編集者) / viewer(閲覧者) |
| added_by | UUID | 任意 | 招待した人。案件の作成者自身の行は空 |
| created_at / updated_at | 日時 | 必須 | |

- 規則: 削除されていない案件には owner が1人以上いる(アプリで保証する)

#### document_series(資料の系列)

一覧の1行にあたる。同じ資料の版をまとめる。

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| project_id | UUID | 必須 | 属する案件(projects.id) |
| created_at / updated_at | 日時 | 必須 | |

- 最新版は、この系列の削除されていない documents のうち version_no が最大のもの
- 削除されていない版が0件の系列は、一覧・検索・資料数に含めない

#### documents(資料の版)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| id | UUID | 必須 | 主キー |
| series_id | UUID | 必須 | document_series.id |
| version_no | 整数 | 必須 | 系列内の版番号。1から連番。削除しても番号は詰めない。(series_id, version_no) で一意 |
| name | 文字列 | 必須 | 1〜200文字 |
| url | 文字列 | 必須 | http / https。同じ系列の中では一意、同じ案件の系列の最新版どうしでも重複させない(アプリで確認) |
| kind | 列挙 | 必須 | google_doc / google_slides / google_sheets / pdf / other |
| google_file_id | 文字列 | 任意 | Google の資料なら URL から取り出した ID。メタデータの取り直しとコピーに使う |
| source_modified_at | 日時 | 任意 | 元の場所での更新日時。連携ありは自動、なしは任意入力 |
| metadata_fetched_at | 日時 | 任意 | 資料名と更新日時を最後に自動取得した日時 |
| created_via | 列挙 | 必須 | link(リンクで登録) / created(新しく作成) / copied(元にして作る・新しい版を作る) |
| registered_by | UUID | 必須 | 登録した人(users.id) |
| deleted_at | 日時 | 任意 | 削除した日時。値があれば削除済み |
| deleted_by | UUID | 任意 | 削除した人 |
| created_at / updated_at | 日時 | 必須 | created_at は登録日時として表示に使う |

#### document_sources(元ネタ)

| カラム | 型 | 必須 | 備考 |
|--------|-----|------|------|
| document_id | UUID | 必須 | 元ネタを持つ側の版(documents.id)。主キーの一部 |
| source_document_id | UUID | 必須 | 元ネタの版(documents.id)。他の案件の資料でもよい。主キーの一部 |
| created_by | UUID | 必須 | 記録した人 |
| created_at | 日時 | 必須 | |

- 規則: document_id と source_document_id は異なる。同じ系列の版どうしは元ネタにできない
- 元ネタの版が削除済みでも行は残し、表示で「削除された資料」とする

### 導出する値

| 値 | 求め方 |
|----|--------|
| 案件の資料数 | 削除されていない版を1件以上持つ系列の数 |
| 一覧の「更新」 | 最新版の source_modified_at。無ければ最新版の created_at |
| 旧版の件数 | 系列の削除されていない版の数 - 1 |
| 案件の最終更新 | 案件内の documents の created_at・source_modified_at・updated_at と、案件の updated_at のうち最大 |
| この資料を元にした資料 | source_document_id が系列のいずれかの版である document_sources の document_id(削除済みは「削除された資料」と表示) |
| 唯一のオーナーの案件数 | その人が owner で、他に owner がいない、削除されていない案件の数 |

## 9. 今後の検討事項

### 拡張候補

- 地図表示: 記録した元ネタと版の関連を地図で俯瞰する。資料が増えて一覧で追えなくなったら足す(`docs/concept.md` の「俯瞰できる」体験)
- 読む順・未読の管理: 案件に後から入った人向けに、読むべき資料と順番を示す
- ドライブの共有設定の同期: 案件内の役割に合わせてドライブの共有を揃える。3つの役割とドライブの権限の対応を詰めてから判断する
- スプレッドシートの「元にして作る」: MVP はドキュメントとスライドだけ。コピーの仕組みは同じなので、要望があれば足す
- ドライブ以外の保存先との連携(Box・OneDrive 等)
- 案件から自分で抜ける操作(オーナー以外)
- 停止された唯一のオーナーの案件の救済(管理者によるオーナーの付け替え等)。MVP は停止時の警告だけ
- 削除済みの案件・資料の復元
- 本文検索: 本文を保存しない方針と引き換えに持たない。必要になったら、本文をどこまで預かるかから決め直す
- 操作の記録(誰がいつ登録・削除したかの履歴画面)
- 招待の通知(メール等)

### 既知の制約

- 連携なしで登録した資料は、リンク先が更新・移動されてもアプリには伝わらない。最新版の正しさは人の登録に頼る
- 会社の Google Workspace で外部アプリとの連携が制限されている場合、連携機能は使えない。中核の管理機能はリンク登録で使える
- 案件内の役割は資料そのものの閲覧権限を与えない。メンバーが資料を開けるかは元の場所の共有設定しだい

### Phase 3 で決めること

- 技術スタック一式
- 「新しく作る」「元にして作る」で作ったファイルのドライブ上の置き場所
- Google の認可情報の保存と暗号化の方法
- 最初の管理者を登録する初期設定の手順
- 画面の URL 設計(ルーティング)
